# Implement a card

Input is a **set code + one or more collector numbers** from that set (e.g. `DKA 76`, or `SOS 1 2 3 4`). If the user gives a card name instead, ask for, or look up, the set/collector number first.

**Multiple collector numbers:** implement each card independently, one at a time — run Steps 2–7 fully for one collector number before moving to the next. This keeps each card's context small and lets a failing card not block the others. Report a short per-card summary (implemented / reprint / tests pass-fail) at the end.

The hard rules in `AGENTS.md` (main branch, no commits, rules accuracy, reuse over creation) apply throughout.

## Step 1 — Gather context

Run the helper once. It loads compact Scryfall data (name, mana, type, oracle, P/T, keywords) through the shared Card Info whole-set cache and runs the reprint check. It stays silent about anything you can derive yourself — file paths and the test command are spelled out in Steps 4/6/7 below, and it flags the tests decision only when tests should be **skipped**. Pass every collector number in one call — the script emits a separate, clearly delimited context block per card:

```
bash -c 'powershell.exe -NoProfile -File scripts/implement-card-context.ps1 <SET> <COLLECTOR_NUMBER> [<COLLECTOR_NUMBER> ...]'
```

`-ClassName` is only valid with a single collector number; with several cards each name is derived from Scryfall. The script is a deterministic lookup only — it does **not** decide the implementation. You do that from the docs in Step 3.

For a **multi-face card** (transform, MDFC, split) the script prints every face's oracle text and then stops, because no class name can be derived from a two-faced name. Decide how — or whether — the engine represents that card before going further; re-run with `-ClassName <Name>` to get the reprint check once you have.

For any additional card lookup, use the configured Scryfall MCP `get_card` tool, and `get_rulings` for a card's official rulings. Never fetch or place raw Scryfall card JSON in model context; the MCP response intentionally omits images, prices, legalities, purchase links, and other fields irrelevant to implementation.

## Step 2 — Reprint short-circuit

If the script reports **EXISTING CLASS FOUND**, this is a reprint: add a single
`@CardRegistration(set = "SET", collectorNumber = "N")` annotation to the existing class and **stop**. Do not implement logic, do not write or run tests.

## Step 3 — Map oracle text to effects (the important part)

Use the docs in this lookup order. **Always `Grep` with keywords from the oracle text — never `Read` these files in full** (they are large):

1. `agent-docs/CARD_PATTERN_INDEX.md` — closest archetype + copy-paste template. Check first.
2. `agent-docs/ORACLE_TEXT_EFFECT_MAP.md` — maps oracle phrases to effect classes + slots.
3. `agent-docs/EFFECTS_QUICK_REFERENCE.md` — compact list of all effects.

Detailed references — grep these when the three above aren't enough:
- `agent-docs/TRIGGER_SLOT_TARGETING.md` — check before implementing a targeted triggered ability.
- `agent-docs/ACTIVATED_ABILITY_GUIDE.md` — `ActivatedAbility` overloads, the trigger quick reference, cost effects.
- `agent-docs/PREDICATES_REFERENCE.md` — every `TargetFilter` / `PermanentPredicate` / `StackEntryPredicate` / `PlayerPredicate` composition.
- `agent-docs/EFFECTS_INDEX.md` — full per-effect descriptions and usage notes.
- `agent-docs/CARD_IMPLEMENTATION_PLAYBOOK.md` — canonical patterns, targeting checklist, anti-patterns, new-effect/predicate checklists.

Apply the reuse-over-creation rule from `AGENTS.md` when choosing effects.

## Step 4 — Write the card class

Create `magical-vibes-card/{letter}/src/main/java/com/github/laxika/magicalvibes/cards/{letter}/{ClassName}.java` extending `Card`, where `{letter}` is the lowercased first letter of the class name (each letter is its own Gradle module, `:magical-vibes-card:{letter}`).

**Cross-letter references:** letter modules can't depend on each other, so a card that is constructed by a card of a *different* letter (a back face via `setBackFaceCard(new X())`, a meld partner, a conjure target, …) lives in `magical-vibes-card/shared/src/main/java/com/github/laxika/magicalvibes/cards/{its letter}/` instead, keeping its `cards.{letter}` package. If your new card constructs such a card, create it there — or `git mv` an existing one there, together with every card it constructs in turn. Same-letter references need nothing special. A misplaced card fails compilation, so `./gradlew :magical-vibes-card:assemble` tells you.

The constructor contains **only engine logic** — `addSpellEffect()` (an instant's or sorcery's effects),
`addCastingCost()` ("as an additional cost to cast this spell"), `addTrigger()` (triggered abilities — see below), `addStaticEffect()` (static abilities, including "enters with …", "as this enters, choose …", dredge, mulligan-time and opening-hand actions — never `Triggers.enters(ObjectRelation.THIS)`, which holds only "when this enters" triggers), `addActivatedAbility()`, `target(...)`, `setNeedsTarget()`, etc. All metadata (name, type, mana, color, subtypes, keywords, P/T, card text) is auto-loaded from Scryfall; never set it. Add the `@CardRegistration` annotation(s). Mirror the structure and comment style of a recent card (e.g. `cards/t/TragicSlip.java`, `cards/t/TorchFiend.java`).

**One Oracle ability is one `addTrigger`.** A triggered ability is one object on the stack (CR 603.3) with every effect it has, in order: "at the beginning of combat on your turn, target creature you control gets +1/+0 and gains haste until end of turn" is `target(creatureYouControl).addTrigger(Triggers.beginningOfCombat(ActivePlayer.YOU), new BoostTargetCreatureEffect(1, 0), new GrantKeywordEffect(Keyword.HASTE, GrantScope.TARGET))`, never two `addTrigger` calls, which are two abilities that go on the stack, and are targeted, separately. An ability of several target groups ("up to one target creature attacks or blocks this combat if able and up to one target creature can't attack or block this combat", Boros Battleshaper) is one `addTrigger` of its effects, each bound to its group with `target(filter, 0, 1).bindEffect(effect)`. Write two `addTrigger` calls only where the card prints two abilities (Lunar Convocation's two end-step abilities, Bloodhall Ooze's two upkeep ones).

**A condition of the trigger event is an event condition.** A condition that is part of the trigger event — "whenever this and at least two other creatures attack", "whenever you attack with three or more creatures", "attacks while saddled", "attacks a battle / an opponent / the monarch", "whenever all non-Wall creatures you control attack", "whenever you attack a player with one or more equipped creatures" — is `TriggerOptions.DEFAULT.withEventCondition(condition)`; "whenever one or more Dragons you control attack" / "whenever you attack with one or more Zombies" is the trigger's filter, `Triggers.youAttack().withFilter(predicate)` ("that many" is `new EventValue()`, the number of matching attackers), and likewise `Triggers.playerAttacks().withFilter(predicate)` for "whenever one or more [filter] attack"; "whenever a player attacks one of your opponents" is `Triggers.playerAttacksOneOfYourOpponents()` (once for each opponent attacked), "whenever your commander attacks" `Triggers.creatureAttacks().withFilter(new PermanentIsCommanderPredicate(true))`; judged only as the ability triggers; `withInterveningIf` is only for an "if" that immediately follows the trigger condition (CR 603.4), checked again as the ability resolves. So is a condition on which the ability exists (a Class's level, a solved Case, a Siege's mode, an unlocked door).

**Triggers on this object's own zone change** ("when this dies", "leaves the battlefield", "is put into a graveyard from …", "is milled", "when you sacrifice this") are written with a real trigger, never an `EffectSlot`: `addTrigger(Triggers.dies(ObjectRelation.THIS), effect)` (bound to a target group: `target(filter).addTrigger(Triggers.dies(ObjectRelation.THIS), effect)`). The factories are `Triggers.dies`, `sacrificed` ("when you sacrifice this"), `leavesBattlefield`, `putIntoGraveyardFrom(Zone.BATTLEFIELD | HAND | LIBRARY, …)`, `putIntoGraveyardFromAnywhere`, `milled`, and `putIntoGraveyardWhileResolving` (haunt on an instant or sorcery). A condition on this object as it last existed ("if it was a creature", "if it had a -1/-1 counter on it", "if it wasn't blocking", "if it was enchanted", "if its power was 3 or greater", "is put into your graveyard") is the trigger's filter, judged as the object left (CR 603.10a): `Triggers.dies(Triggers.CREATURE, ObjectRelation.THIS)`, `Triggers.dies(new PermanentHasCountersPredicate(CounterType.MINUS_ONE_MINUS_ONE), ObjectRelation.THIS)`. Any other intervening "if" (CR 603.4: "when this dies, if you have no cards in hand, …") is an option: `addTrigger(Triggers.dies(ObjectRelation.THIS), TriggerOptions.DEFAULT.withInterveningIf(new ControllerHandEmpty()), effect)` (also on a target group). A condition the trigger event itself requires ("whenever this creature attacks **while** you control a Dinosaur", "attacks alone", "an opponent draws a card during their turn", "when the fourth plan counter is put on this", "whenever you roll a 4 or higher") or one under which the ability exists at all ("Max speed —", a station, level or Spaceship threshold, an unlocked door, a chosen mode) is the event condition `TriggerOptions.DEFAULT.withEventCondition(condition)`: it is checked as the event occurs and never again as the ability resolves (CR 603.2), where an intervening "if" (`withInterveningIf`) is checked both times (CR 603.4). Never write a `ConditionalEffect` for either: `ConditionalEffect(condition, effect)` is the "if" of an effect, checked only as the effect resolves. A triggered ability's intervening "if" ("When/Whenever/At [trigger event], if [condition], [effect]", CR 603.4) is never a `ConditionalEffect`: write it as `TriggerOptions.DEFAULT.withInterveningIf(condition)`, which the collector checks as the ability triggers and wraps around its effects to check again as it resolves; a condition of the trigger event is `withEventCondition(condition)` (CR 603.2). An "if" anywhere else in the text ("draw a card if …", "Then if …", "If …, instead …") is a `ConditionalEffect`. And "this ability triggers only once each turn" is `TriggerOptions.DEFAULT.withLimit(TriggerLimit.ONCE_EACH_TURN)`; when one Oracle ability has two trigger conditions, build one `TriggeredAbility` with both so its limit covers them (Oni-Cult Anvil). Never wrap these abilities' effects in `ConditionalEffect` or another wrapper: a `ConditionalEffect` is only for a check that isn't an intervening "if" ("you may exile it. If you do", which needs the card still in your graveyard). One `addTrigger` call is one triggered ability, so a trigger with several effects ("draw a card and gain 2 life") passes them all to the one call. A grant of such an ability takes `new TriggeredAbility(Triggers.dies(ObjectRelation.THIS), effect)` where older grants took a slot and an effect. **Another object dying** ("whenever a creature dies", "whenever another creature you control dies", "a nontoken creature", "equipped creature", "a creature dealt damage by this creature this turn", "the creature it haunts") is a real trigger too: `addTrigger(Triggers.creatureDies(ObjectRelation.R), effect)`, `Triggers.nontokenCreatureDies(R)`, `Triggers.dies(Triggers.CREATURE_OR_PLANESWALKER / ARTIFACT_OR_CREATURE, R)` or `Triggers.dies(ObjectRelation.HAUNTED)`. Pick `R` from the wording: "a creature you control" → `YOU_CONTROL` (includes this creature: it sees its own death), "another creature you control" → `ANOTHER_YOU_CONTROL`, "this creature or another creature you control" → `THIS_OR_ANOTHER_YOU_CONTROL`; without "you control" → `ANY`, `ANOTHER`, `THIS_OR_ANOTHER`; "an opponent controls" → `OPPONENT_CONTROLS`; "equipped creature" → `EQUIPPED`; "enchanted player controls" → `ENCHANTED_PLAYER_CONTROLS`; "dealt damage by this creature" / "by equipped creature" → `DAMAGED_BY_THIS` / `DAMAGED_BY_ATTACHED`. Never add a `Triggers.dies(THIS)` copy for the source's own death. "Whenever one or more creatures die" passes `TriggerOptions.ONE_OR_MORE`: `addTrigger(new TriggerCondition(trigger), TriggerOptions.ONE_OR_MORE, effect)`; "while this card is in your graveyard" passes `new TriggerCondition(trigger, AbilityZones.GRAVEYARD)`. A restriction on the creature that died ("another Zombie", "a nontoken Vampire", "a creature with power 5 or greater", "a creature with a -1/-1 counter on it", "a creature blocking this creature", "if it was a Human", "if it had counters on it") is the trigger's filter, judged on the creature as it last existed (CR 603.10a): `Triggers.creatureDies(new PermanentHasSubtypePredicate(CardSubtype.ZOMBIE), ObjectRelation.ANOTHER_YOU_CONTROL)`, `Triggers.nontokenCreatureDies(filter, R)`, `Triggers.dies(new PermanentAllOfPredicate(List.of(Triggers.CREATURE_OR_PLANESWALKER, filter)), R)`. Write it with permanent predicates (`PermanentHasSubtypePredicate`, `PermanentColorInPredicate`, `PermanentHasKeywordPredicate`, `PermanentIsTokenPredicate`, `PermanentHasCountersPredicate`, `PermanentPowerAtLeastPredicate`, …), never a card predicate. "This creature or another [restricted] creature" is one ability, `THIS_OR_ANOTHER_YOU_CONTROL` / `THIS_OR_ANOTHER` with the filter: the source matches whatever it was. An intervening "if" about whichever creature died ("whenever this creature or another creature you control dies, if it had counters on it") covers the source too, so it is one `TriggeredAbility` with two trigger conditions and the same filter, `Triggers.dies(filter, THIS)` and `Triggers.creatureDies(filter, ANOTHER_YOU_CONTROL)`, added with `addTriggeredAbility` (`SpellTarget.addTriggeredAbility` for a target group; Reluctant Role Model, Cass, Hand of Vengeance). "Dies during your turn" is `.onlyDuringYourTurn()`; any other intervening "if" ("if you have the city's blessing", "if that creature's power is greater than this creature's") is `TriggerOptions.DEFAULT.withInterveningIf(condition)`; "this ability triggers only once each turn" is `TriggerOptions.DEFAULT.withLimit(TriggerLimit.ONCE_EACH_TURN)` and "do this only once each turn" `TriggerLimit.DO_ONLY_ONCE_EACH_TURN` (`TriggerOptions.ONE_OR_MORE.withLimit(…)` for "one or more"). Never wrap these effects in an intervening-if `ConditionalEffect`; a check that is part of the effect ("put a +1/+1 counter on it. If that creature was a Villain, draw a card") stays in the effect. **Other objects' zone changes** are real triggers too, with the same relations plus `YOU_OWN` / `ANOTHER_YOU_OWN` / `OPPONENT_OWNS` for "put into your / an opponent's graveyard", "leaves your graveyard", "returned to your hand" (a card goes to its owner's zones), `ENCHANTED` for "enchanted permanent": `Triggers.sacrificed(filter, R)` ("whenever you sacrifice a permanent" `YOU_CONTROL`, "an opponent sacrifices" `OPPONENT_CONTROLS`, "a player sacrifices" `ANY`), `sacrificedOrDestroyed`, `destroyed`, `dies(filter, R)` ("whenever an artifact is put into a graveyard from the battlefield" `dies(Triggers.ARTIFACT, ANY)`), `leavesBattlefield(filter, R)`, `leavesBattlefieldWithoutDying`, `putIntoGraveyardOrExileFromBattlefield`, `exiledFrom(Set.of(Zone.…), filter, R)` (`Set.of()` for anywhere), `putIntoHandFrom(Zone.BATTLEFIELD | LIBRARY | GRAVEYARD, filter, R)`, `putIntoGraveyardFrom(Zone.LIBRARY, …)`, `putIntoGraveyardFromAnywhere(filter, R)`, `putIntoGraveyardFromAnywhereButBattlefield`, `milled(filter, R)`, `mills(filter, R)` (a mill wherever the card ends up), `leavesGraveyard(filter, R)`, `putIntoLibrary`, `putIntoCommandZone`. Filters are the `Triggers` constants (`CREATURE`, `NONTOKEN`, `NONTOKEN_CREATURE`, `ARTIFACT`, `NONTOKEN_ARTIFACT`, `ENCHANTMENT`, `LAND`, `LAND_CARD`, `NONLAND`, `NONCREATURE`, `NONCREATURE_ARTIFACT`, `PERMANENT_CARD`, `TOKEN`, `AURA_OR_EQUIPMENT`, `ARTIFACT_OR_CREATURE`, `BLACK_CARD`, `NONBLACK_CARD`) or `null`. "During your turn" is `.onlyDuringYourTurn()`, "a spell or ability an opponent controls causes …" `.causedBy(PlayerRelation.OPPONENT)`. A restriction beyond those constants ("whenever you sacrifice a Food", "a nontoken artifact", "a legendary permanent", "a token you control leaves", "if it had counters on it", "a Kithkin card is put into your hand") is the trigger's filter, judged on the object as it last existed or as it is after the change: the restriction itself where the wording's constant is `null` (`Triggers.sacrificed(new PermanentHasSubtypePredicate(CardSubtype.FOOD), ObjectRelation.YOU_CONTROL)`), `new PermanentAllOfPredicate(List.of(constant, restriction))` otherwise (`Triggers.dies(new PermanentAllOfPredicate(List.of(Triggers.NONTOKEN, new PermanentHasSubtypePredicate(CardSubtype.CURSE))), ObjectRelation.YOU_OWN)`), with permanent predicates. "An artifact you control" / "a permanent you control" is the relation (`Triggers.dies(Triggers.ARTIFACT, ObjectRelation.YOU_CONTROL)`, "another" `ANOTHER_YOU_CONTROL`). A permanent phasing, transforming or being turned face up takes the same filters, and "if it's your turn" there is `TriggerOptions.DEFAULT.withInterveningIf(new ControllerTurn())`. Any other intervening "if" and the limits are `TriggerOptions` as for the source's own zone change. Never wrap these abilities' effects in an intervening-if `ConditionalEffect`. "This [permanent] or another [restricted] one" is one ability with two trigger conditions, the source's own (`…(ObjectRelation.THIS)`) and the other one's (`…(filter, ObjectRelation.ANOTHER_YOU_CONTROL)`): `addTriggeredAbility(new TriggeredAbility(List.of(new TriggerCondition(other), new TriggerCondition(own)), TriggerOptions.DEFAULT, List.of(new EffectRegistration(effect))))` (Slayer's Bounty, Costume Closet). **Another object entering** ("whenever a creature you control enters", "another creature", "an artifact", landfall, constellation, "a token", "a creature an opponent controls", "from a graveyard", "from exile", "enters transformed") is `Triggers.enters(filter, R)` / `Triggers.entersFrom(Zone.GRAVEYARD | EXILE, filter, R)` with the filters above plus `EQUIPMENT`, `TRANSFORMED` and `CREATURE_OR_ENCHANTMENT`; a restriction on the entering object ("another Elf", "a nontoken creature", "a creature with power 4 or greater", "if it entered from a graveyard", "if it wasn't cast", "enters tapped") is the trigger's filter, written with permanent predicates and judged on the permanent as it entered: `Triggers.enters(new PermanentAllOfPredicate(List.of(Triggers.CREATURE, new PermanentHasSubtypePredicate(CardSubtype.ELF))), ObjectRelation.ANOTHER_YOU_CONTROL)` (its origin and state are `PermanentEnteredOrCastFromZonePredicate(Zone.GRAVEYARD)`, `PermanentNotPredicate(new PermanentWasCastPredicate())`, `PermanentNotPredicate(new PermanentCastFromZonePredicate(Zone.HAND))`, `PermanentIsTappedPredicate`, `PermanentPowerAtLeastPredicate`), "this creature or another [X] you control" is `THIS_OR_ANOTHER_YOU_CONTROL` with the filter `AllOf(Triggers.CREATURE, X)` (the source counts whatever its subtypes are), "this [permanent] or another [enchantment, artifact, Equipment, land, …] you control enters" (no creature watch sees the source's own entry) is one `TriggeredAbility` with two trigger conditions, the source's own and the other one's: `addTriggeredAbility(new TriggeredAbility(List.of(new TriggerCondition(Triggers.enters(ObjectRelation.THIS)), new TriggerCondition(Triggers.enters(Triggers.ENCHANTMENT, ObjectRelation.ANOTHER_YOU_CONTROL))), TriggerOptions.DEFAULT, List.of(new EffectRegistration(effect))))` (`target(filter).addTriggeredAbility(…)` for a target group; Eidolon of Blossoms, Whitewater Naiads, Field of the Dead), never two abilities, "a [X] you control" is `YOU_CONTROL` (the source then has to match the filter too), "during your turn" is `.onlyDuringYourTurn()`, an intervening "if" is `TriggerOptions.DEFAULT.withInterveningIf(condition)`, "this ability triggers only once each turn" is `withLimit(TriggerLimit.ONCE_EACH_TURN)` and "do this only once each turn" `DO_ONLY_ONCE_EACH_TURN`, never an intervening-if `ConditionalEffect` around the effect; "one or more" (and "whenever one or more tokens you control enter") passes `TriggerOptions.ONE_OR_MORE`, and the triggers a landfall or Curse ability's text puts in one ability are one `addTrigger` call. The source's own "when this enters" is `addTrigger(Triggers.enters(ObjectRelation.THIS), effect)` (bound to a target group: `target(filter).addTrigger(Triggers.enters(ObjectRelation.THIS), effect)`; simultaneous effects: `addSimultaneousTrigger(Triggers.enters(ObjectRelation.THIS), a, b)`); "when this enters, if …" (an intervening "if", CR 603.4) is `addTrigger(Triggers.enters(ObjectRelation.THIS), TriggerOptions.DEFAULT.withInterveningIf(condition), effect)`, and "this ability triggers only once each turn" `withLimit(TriggerLimit.ONCE_EACH_TURN)`, which covers every trigger condition of the ability (Oasis of Renewal). The intervening "if"s that keywords define are options too: ravenous's "if X is 5 or more" (`SpellXAtLeast(5)`), offspring's and kicker's `Kicked`, squad's `RepeatedAdditionalCostPaid`, gift's `GiftPromised`, and "when this land enters untapped" (`SourceUntapped`). Never wrap an own enters ability's effects in `new ConditionalEffect(…)`: an "If …" sentence inside the effect text ("When this enters, tap target creature. If you control …, it doesn't untap") is no intervening "if" and is `new ConditionalEffect(condition, effect)`, checked only as the ability resolves; on a fact fixed as the permanent entered ("… instead" or "Then if …" on kicked, an alternative cost, the gift, X) the enters collector reads the same condition as the ability triggers, with the same result (Desolation Angel). Each "when this enters" ability is one object on the stack (CR 603.3): one Oracle ability is one `addTrigger` of all its effects, never one `addTrigger` per effect, and a second, separate "when this enters" ability is a second `addTrigger`. When an ability's effects target through different target groups or none ("target player mills two cards. You gain 2 life"), declare each targeted effect as a local variable, bind it with `target(filter).bindEffect(effect)`, and add every effect in one `addTrigger(Triggers.enters(ObjectRelation.THIS), mill, new GainLifeEffect(2))` (Watcher of the Wayside, Gurmag Rakshasa). **Phasing, transforming and turning face up** are `Triggers.phasesOut` / `phasesIn` (filter, R), `transformsToBackFace(THIS)` / `transformsToFrontFace(THIS)` ("when this transforms into [face]"), `transforms(filter, R)` ("whenever a permanent you control transforms", "equipped creature" `EQUIPPED`) and `turnedFaceUp(filter, R)` ("when this is turned face up" `THIS`). "As this is turned face up …" (megamorph counters, a copy or P/T choice, attaching an Aura; CR 614.1e) is a static ability (`addStaticEffect`), and "as this transforms into [this face], …" is `addStaticEffect(new AsTransformsIntoThisEffect(effect))` on that face; neither is a trigger. These triggers are the keys of the engine's `ZoneChangeWatch`: a combination no watch lists doesn't trigger, so grep `ZoneChangeWatch.java` for the slot-like name of the wording and copy its trigger exactly. **The beginning of a step or phase** ("at the beginning of your upkeep", "each upkeep", "each opponent's end step", "at the beginning of combat on your turn", "at end of combat", "your precombat / postcombat / second main phase", "enchanted player's upkeep") is `addTrigger(Triggers.upkeep(ActivePlayer.P), effect)` with `Triggers.upkeep`, `drawStep`, `precombatMainPhase`, `beginningOfCombat`, `endOfCombat()`, `postcombatMainPhase`, `secondMainPhase` or `endStep`, and `P` from the wording: "your" `YOU`, "each" `ANY`, "each opponent's" `OPPONENT`, "enchanted player's" `ENCHANTED_PLAYER`, "enchanted creature's / permanent's controller's" `ENCHANTED_PERMANENT_CONTROLLER`. A Curse's "at the beginning of each end step, enchanted player …" is `endStep(ANY)`, and "at the beginning of your upkeep, enchanted permanent's controller …" is `upkeep(YOU)` on the Aura's target group; the collectors give such an ability the enchanted player as its player. From another zone pass the zone: `addTrigger(new TriggerCondition(Triggers.upkeep(ActivePlayer.YOU), AbilityZones.GRAVEYARD), TriggerOptions.DEFAULT, effect)` (graveyard, exile, command zone). One Oracle ability is one `addTrigger` of all its effects ("add {U}{R}" is `addTrigger(trigger, addBlue, addRed)`), never one `addTrigger` per effect: the step readers read the abilities themselves and judge their options (`StepAbilityReader`). **Spells, land plays and activations** are real triggers too: "whenever you cast a spell" `Triggers.youCastSpell()`, "an opponent casts" `opponentCastsSpell()`, "a player casts" `playerCastsSpell()`, "when you cast this spell" `youCastThisSpell()` (functions from the stack), `youCopySpell()` / `opponentCopiesSpell()`, `youCounterSpell()`, `yourSpellCountered()`, `thisSpellCounteredOrFizzles()`, `youPlayLand()` / `youPlayAnotherLand()` / `opponentPlaysLand()`, `youActivateAbility()` / `opponentActivatesAbility()` (mana abilities included), `youActivateNonManaAbility()` / `opponentActivatesNonManaAbility()`, `youActivateExhaustAbility()`, `youActivateEternalizeOrEmbalm()` and `thisManaAbilityResolves()`. ## Step 5 — Only if a new effect is genuinely needed

After confirming no existing effect/combination works — read `agent-docs/ARCHITECTURE.md` first (engine invariants: card freezing, layer system, thread safety, Jackson 3 imports). **Never add a new `instanceof <ConcreteEffect>` outside `service/effect/**` / `service/validate/**` — no build check catches it any more, so it is on you.** Register the effect's knowledge in the ONE place that owns it:
1. Add a record implementing `CardEffect` in `magical-vibes-domain/.../model/effect/`.
2. Add resolution as a `@Component` implementing `NormalEffectHandlerBean` (declaring `handledEffect()`) under `service/effect/normalfx/` — NOT via `instanceof` in `GameService`. For a continuous/static effect use a `StaticEffectHandler` under `service/effect/staticfx/` instead (see `agent-docs/STATIC_EFFECT_HANDLERS.md` / `LAYER_SYSTEM.md`).
3. **If the effect is targeted** (a single-`targetId` spell or activated ability), override `targetSpec()` on the effect record to return a non-NONE `TargetSpec` (category + `harmful` flag + optional `PermanentPredicate`) — the declarative interpreter narrows the legal target type; leaving it at `NONE` gives the cast path no type checking (Fireball-burns-a-Plains bug). A `@ValidatesTarget(YourEffect.class)` validator under `service/validate/` is now ONLY an escape hatch for non-structural rules, and still needs the structural spec. See `agent-docs/EFFECTS_INDEX.md` § "Effect targeting declarations" and `agent-docs/TRIGGER_SLOT_TARGETING.md` § "Spell / activated-ability target validation".
4. **If the effect fits an AI-scored family**, implement the matching capability interface in `model/effect/` (`DamageDealingEffect`, `RemovalEffect`, `ManaProducingEffect`, `CardDrawingEffect`, `LifeGainEffect`, `TokenCreatingEffect`, `CreatureBoostEffect`, `StaticCreatureBoostEffect`, `KeywordGrantingEffect`, `ControlStealingEffect`, `CounterSpellingEffect`, `RegenerationEffect`) so the AI reads a FACT, not the type. See `agent-docs/EFFECTS_QUICK_REFERENCE.md` § "Capability / marker interfaces".
5. If Scryfall returns a new subtype/keyword, add it to `CardSubtype` / `Keyword`.
6. If the effect needs a new view flag, update `CardView` / `CardViewFactory` and the frontend `Card` interface in `websocket.service.ts`.
7. **Update the relevant `agent-docs/` files** so the new effect is discoverable.
8. If a service you extended has unit tests, add tests for the new behavior too.

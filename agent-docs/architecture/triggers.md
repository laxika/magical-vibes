# Triggers

Triggered abilities: rules events, the trigger pipeline, the collectors, and what a stack entry records about its trigger event. Never read whole: grep for the class or wording you are changing and read that paragraph.

- **Rules events and the trigger pipeline**: `GameData.rulesEvents` (`model/rules/RulesEventLog`) records synchronous `RulesEvent`s inside the action, grouped into one `RulesEventBatch` per occurrence (CR 603.2c); unlike domain events, rules code reads them. Zone changes (`ZoneChangeEvent`: card, from, to, cause, last-known permanent, controller) are emitted at three kinds of choke point: `PermanentRemovalService.processRemovalCleanup` for every battlefield departure (snapshot from `DepartureService`'s batch snapshot when there is one, CR 603.10a), `BattlefieldPlacementService.completePlacement` for every entry, and GameData's own hand, library, graveyard, exile, command-zone and stack lists for every other arrival, so a card added straight to one of those lists is still a zone change. The log remembers each card's last zone, so an arrival names where the card came from; a move inside one zone emits nothing, and a departure that a replacement sends elsewhere (CR 614.6) is rewritten rather than doubled. Engine code that moves a card for a reason names it around the move (`setCause`/`restoreCause`: destroy, sacrifice, discard, mill), and code that moves several cards at once opens a scope (`beginBatch`/`endBatch`; the permanent-leave, graveyard-leave and card-exile batch scopes and mill already do). Anything that refills zone lists without moving cards (simulation copies, the turn-restart restore) must run between `suppress()` and `resume()`. Every leave path in `PermanentRemovalService`, GraveyardService's `addCardToGraveyard`, mill and the Aura sweeps open a scope, so a departure's batch closes only after its card arrived (and was redirected). Each batch goes, as it closes, to the trigger pipeline (`service/trigger/pipeline`: `RulesEventPipeline` → `TriggerIndex` candidates → `TriggerMatcher` → `TriggeredAbilityStackService`), registered on every game by `GameSetupService` and carried into simulation copies; `beginTriggerOrder` only drains closed batches afterwards. The pipeline puts abilities with a real `Trigger` (`ZoneChangeTrigger` via `Triggers`, added by `Card.addTrigger` or `SpellTarget.addTrigger`, granted as `new TriggeredAbility(trigger, effect)`) on the stack with their `TriggerOptions` (intervening "if", limits, multiplicity, and the event condition: a condition the trigger event itself requires, checked as the ability triggers and not again on resolution, CR 603.2) and additional-trigger copies. No triggered ability has a legacy view any more (step 14, run 16q): every collector reads the abilities, their filters and options. Every zone change but "when this enters" and every permanent change is read as an ability by the pipeline, which judges its filter and options, and by the readers outside it (face-up planes, schemes, the abilities a resolved spell registered) through `ZoneChangeAbilityReader`, which takes an ability without options and throws on any other. The ability rejects "once each turn for each creature" and a trigger mode as it is built. A permanent phasing, transforming or being turned face up is a `PermanentChangeEvent` (not a zone change, CR 702.26d), matched the same way against `PermanentChangeTrigger`s (`Triggers.phasesOut`, `phasesIn`, `transforms`, `transformsToBackFace`, `transformsToFrontFace`, `turnedFaceUp`); a phasing-out permanent's own abilities look back to it as it was (CR 603.10b). "As this is turned face up" and "as this transforms into" are static abilities, applied at the choke point. Every "when this dies / leaves the battlefield / is put into a graveyard from … / is milled / when you sacrifice this" ability is one now (the old `ON_DEATH`, `ON_SELF_LEAVES_BATTLEFIELD` and `ON_SELF_PUT_INTO_GRAVEYARD_FROM_*` slots are gone), and so is every "whenever [a creature, another creature you control, a nontoken creature, equipped creature, the creature it haunts, …] dies" ability (the old `ON_*_CREATURE_DIES` slots are gone). A trigger's `ObjectRelation` and filter say which moving object it watches and whether that can be the source itself ("a creature you control" includes it, "another" doesn't, "this or another" always does). `TriggerIndex.observerCandidates` lists the other objects that see a permanent die, as they were just before the event (CR 603.10a): the battlefield, the permanents that left in the same batch (their departure events), graveyard cards that were there before it and the exiled cards that haunted it; the filter is judged on the departed copy's last-known card. Their abilities go on the stack through `TriggeredAbilityStackService.triggerOnce`, which hands them to `TriggerCollectionService.triggerCreatureDeath`/`triggerCreatureDeaths`: the old per-slot collectors' bodies, picked by `CreatureDeathWatch`, with their handlers in `DeathTriggerCollectorService.dispatchCreatureDeath` (until step 15). "One or more" deaths is `TriggerMultiplicity.ONE_OR_MORE`. Death triggers a resolved spell registered, emblems', the delayed watchers and planes' are still collected at the choke point (`checkCreatureDeathRegisteredTriggers`). The source's own zone-change abilities carry no trigger-only wrapper: a condition on the object as it last existed is the `THIS` trigger's filter (`TriggerMatcher` judges it on the last-known copy), any other intervening "if" and the limit are `TriggerOptions`. Nor do other objects' zone-change and permanent-change abilities, but for "another object enters" (step 12a's `ZoneChangeWatch` family): a restriction on the moved object is the trigger's filter and "you control" its relation, and `ZoneChangeWatch.of` finds the watch of a trigger narrowed that way (filter `AllOf(X, …)` → the watch of filter `X`, any other filter → the watch of no filter, unless `CreatureDeathWatch.collects` claims a dies trigger; `onlyDuringYourTurn()` → the watch without it; `whileCasting(CardPredicate)`, "while casting a spell with emerge", is judged by `TriggerMatcher` on `ZoneChangeEvent.castingSpell`, the spell `RulesEventLog.setCastingSpell` names while its costs, or a mana ability activated with a cast `ManaPaymentIntent`, are paid). The watch bodies take the "do this only once each turn" limit from the ability (`TriggerMatchContext.markSourceOncePerTurnOnAcceptance`), and "this or another [restricted] one" is one ability with a `THIS` condition, collected by the source's own path, and an `ANOTHER_…` condition, collected by its watch. The source's own zone-change ability ("when this dies", "leaves the battlefield", "is put into a graveyard from anywhere", "when you sacrifice this") goes on the stack through the stack door (`TriggeredAbilityStackService.trigger` hands it to `put`) with one record whatever its effects are (`ownZoneChangeRecord`): the source as it last existed (snapshot, triggering permanent with its attachments, last-known power as the event value, mana value, how it was cast), the card with its new zone's incarnation (CR 400.7) and the card its linked ability exiled (CR 607.2a); the door announces its mode and chooses its targets like any ability's, a graveyard target an own departure's effect describes itself ("return any number of target Spirit cards", Iname, Life Aspect) included, judges "another target card" against the source's physical card (a copy's, Gixian Puppeteer) and evaluates a graveyard target's mana value limit with the departed permanent as it last existed (Soulshift, CR 603.10a). "A creature dying causes an ability to trigger an additional time" (Teysa Karlov) is the request's `withCreatureDying()`, which an ability that triggers on a sacrifice doesn't set (her ruling). Another object's zone change, phasing, transforming or being turned face up goes through `triggerOnce` / `triggerPermanentChange`: the collector (`TriggerCollectionService.zoneChangeRequest` / `permanentChangeRequest`) judges what the watch adds (the watcher's own move, the commander, "for the first time each turn", Torpor Orb's kind) and records the event (`zoneChangeRecord`: a departure as above, an entry with the entering permanent's controller, power, toughness and the player it attacks, a card's move with its stay, "one or more" as the batch's objects and count or total power, "that player" as the non-targeting target and triggering player), and the door puts it; an entering doubler (Panharmonicon) reads the request's `TriggerContext.PermanentEnters` event. Every zone-change watch and every creature-death watch (`CreatureDeathWatch`) goes through the door (`TriggerCollectionService.zoneChangeRequest`, whose `zoneChangeRecord` records the death or departure whatever the effects are); only the watches `keepsLegacyPermanentChangeRoute` lists (face-up and transform) still go to their old putters. A "whenever one or more tokens enter" ability triggers once for the batch and a "whenever a token enters" one once for each token: the card writes which (CR 603.2c), and no effect's resolution condition splits a batch. A permanent that left the battlefield is the record's triggering permanent with its owner, and its card's exile stay only when the card is in exile. The door chooses a graveyard target the effect describes itself (`GraveyardTargetingSupport.findTarget`: Iname, Exhumer Thrull's haunted creature) for any departure event, its mana value limit judged with the departed permanent as source and the record as the entry (`AmountEvaluationService.evaluateAtDeath`, so `TriggeringPermanentManaValue` reads the last-known object, CR 603.10a). "Other than it" of a graveyard target is `CardIsTriggeringCardPredicate`, bound to the record's triggering card as the target is chosen (`AmountEvaluationService.bindTriggeringCard`); `CardIsSelfPredicate` is the source's card. A door choice pump (`processNextAttackTriggerTarget`, `processNextETBTokenMultiTargetTrigger`, `processNextSpellGraveyardTargetTrigger`, `processNextTriggeredModalTrigger`) begins nothing while a choice awaits input, so a second caller can't write over the prompt and lose a parked ability. A departure event carries what look-back abilities read just before the permanent left (CR 603.10a): its last-known permanent (with the permanents that damaged it this turn), the zone-change abilities other permanents granted it, its attachments, the exiled cards that haunted it, Hushbringer's suppression and the spell whose cost it paid. "At the beginning of [player's] [step or phase]" abilities have a real `StepTrigger` too (`Triggers.upkeep`, `drawStep`, `precombatMainPhase`, `beginningOfCombat`, `endOfCombat`, `postcombatMainPhase`, `secondMainPhase`, `endStep`, with an `ActivePlayer`: `YOU`, `ANY`, `OPPONENT`, `ENCHANTED_PLAYER`, `ENCHANTED_PERMANENT_CONTROLLER`; CR 603.2b). A step beginning is no rules event: `StepTriggerService` still collects them where the old step slots were collected, with each step's old grouping and target routing. A step ability is matched by the step's rules event (`StepEvent`, below). A step ability goes on the stack as one object (CR 603.3); one Oracle ability is one `addTrigger` of all its effects (Abstract Paintmage, Sanctum of Stone Fangs). Code that only inspects which effects a card has (cumulative upkeep, the conspiracy marker, the Oath active-player check, Wall of Nets) reads the raw effects (`Card.getTriggerEffects`). A plane's step abilities are the step event's candidates; its planeswalk, encounter and chaos readers (`PlanechaseService.trigger`) judge each ability's event condition (`MiscAbilityReader` rejecting what they can't read) and hand it whole to the stack door with the planar object it is of (`sourcePlanarObject` on the record). Spells, land plays and activations have real triggers as well: `SpellTrigger` (cast, "cast this spell", copied, counters, countered, "this spell is countered or fizzles"; CR 601.2i), `LandPlayTrigger` (CR 116.2a) and `AbilityTrigger` (activated, non-mana, exhaust, embalm or eternalize, "a mana ability of this resolves"), built by named `Triggers` factories (`youCastSpell()`, `opponentCastsSpell()`, `youCastThisSpell()`, `youPlayLand()`, `youActivateNonManaAbility()`, …). Each such event is a `SpellEvent` (`Cast`, `Copied`, `Countered`, `SpellCountered`, `CounteredOrFizzled`, `CardAdvantage`, `LandPlayed`, `Activated`, `ManaAbilityResolved`), emitted as an occurrence of its own where the action completes and matched by `SpellTriggers`: a permanent's or face-up scheme's abilities as the layers leave them (`TriggerIndex.permanentAbilities`, a printed one's spell filter and effects through its text changes, CR 612.1), the planes', the abilities a resolution registered, the emblems', suspended cards' and the caster's graveyard, hand, exile and command-zone cards'. A cast or copy ability is judged by its `SpellFilter` (`SpellFilter.ANY` for "a spell"), a land-play one with a filter or zone by its `LandPlayTrigger`, an activation one by its `AbilityTrigger`'s event, player, kind, source, stack-entry filter and payment; any other by its event condition alone (`SpellTriggers.collectUnfilteredAbility`), and every one goes to the stack door with the event's record (`spellWatchRecord`: the land played and the player who played it, the mana ability's activator and the mana it produced, the countered spell; the cast record; the activation record), the door judging its intervening "if" and limit. The engine's keyword and delayed cast abilities stay in `TriggerCollectionService.checkSpellCastTriggers` around the `Cast` event. The "when you cast this spell" reader puts the card's own and perpetually granted abilities through the stack door (`putSelfCastAbility`) and the engine's granted replicate and demonstrate through `collectSelfCastAbilities`, each as one object (CR 603.3), and records the spell (its X, kick, cast zone and the spell itself) as the entry's triggering spell whatever the effects are; a "you may" is asked as it resolves (CR 603.5). A cast trigger with `.grantedToTheSpell()` ("spells you cast … have cascade") is the spell's ability: each effect its own object sourced by the spell, never triggered additional times. A granted ability with a limit is the granting permanent's instance of it (`TriggeredAbility.instance()`, set by `GrantTriggeredAbilityEffectHandler`), so each grant keeps its own limit (CR 113.2c). The activation collectors read every activation ability itself (`TriggerCollectionService.activationAbilities`, by `AbilityTrigger.unfiltered()`): `activationTriggers` judges the trigger's ability kind (`youActivateAbility().withKind(AbilityTrigger.AbilityKind.LOYALTY)`, `AbilityKind.matches(ActivatedAbility)`) and source filter (`.withSource(permanentPredicate)`, from the watcher's point of view) and the event condition, and the stack door the limit and the intervening "if" ("if mana from a Treasure was spent to activate it", an `EventFactCondition` the context carries, judged once). A land-play trigger's filter or zone (`youPlayLand().withFilter(cardPredicate)`, `.playedFrom(Zone.EXILE)`, `.notPlayedFrom(Zone.HAND)`) makes it its own `watchKey()` too: `SpellTriggers.collectLandPlayAbility` which judges the filters and the event condition and hands the ability to the stack door, the player who played the land as "that player" and the land as the triggering card, its targets chosen as it goes on the stack. A cast trigger's `SpellFilter` (`youCastSpell().withFilter(cardPredicate).withStackEntryFilter(…).duringYourTurn().nthThisTurn(2)…`, or `.anySpell()`) marks an ability the generic spell-cast collector reads itself, not through the legacy view: a filtered `SpellTrigger` is its own `watchKey()`, and `SpellTriggers` (for a permanent, an exile, graveyard, hand or command-zone card and a plane alike) hands it to `collectCastAbility` as a `CastAbility` (the filter and the ability), which judges the filter and the event condition and hands the ability to the stack door: one stack object of its effects as written (CR 603.3), a "you may" or "you may pay" asked as it resolves (CR 603.5) and the targets of what it offers chosen as it goes on the stack (`MayEffect` and `MayPayManaEffect` give the offered effect's `targetSpec`, CR 603.3d), its limit and intervening "if" judged by the door. The dispatch reads the filter through the permanent's text changes (`TextChangeTransformer.transformSpellFilter`). The filter also names the zone the spell was cast from (`.castFrom(zone)` / `.notCastFrom(zone)`, judged from the cast event's zone; the spell counts then count that zone's spells), a kicked spell (`.kicked()` / `.eachKick()`, the kick count the stack entry's event value) and whose spells the counts count (`.countingEveryPlayersSpells()`). A copy trigger's filter (`youCopySpell().withFilter(…)`, spell and stack-object conditions only) is read the same way (`collectCopyAbility`, every spell type); those collectors take a missing target filter from the bound target group too. A cast trigger without a filter is still collected by its effect's class (the effects that bind the spell or its caster, until step 15). No collector unwraps a "you may" to find a handler: `TriggerCollectorRegistry.dispatch` picks a handler by the effect's own class, then the watch's default (the creature-death watches and the source's own zone changes have only their default), so a `MayEffect`, `MayPayManaEffect` or `MayPayTapPermanentsEffect` around a class-keyed effect reaches only a handler registered for the may class itself (CR 603.5: the option is the ability's, asked as it resolves). A cast ability's "while …" (`TriggerOptions.withEventCondition`, `CastAbility.eventCondition`) is checked only as the spell is cast (CR 603.2), never again as the ability resolves. A temporary global cast trigger with a spell filter ("until end of turn, whenever you cast an instant or sorcery spell, copy it") is collected by the generic cast collector too. Granted abilities are found by their trigger's `watchKey()` too (`TriggeredAbility.hasWatchedTrigger`). Combat triggers have a real `CombatTrigger` (a `CombatEvent`: attacks, attacks you, one or more attack, attacks and isn't blocked, blocks, becomes blocked, combat damage to a player, creature, planeswalker, battle, you, its owner, …; an `ObjectRelation` for whose creature: `THIS`, `YOU_CONTROL`, `ANY`, `EQUIPPED`, `ENCHANTED`, `OPPONENT_CONTROLS`; and an optional filter), built by named factories (`Triggers.attacks()`, `creatureYouControlAttacks()`, `youAttack()`, `blocks()`, `becomesBlocked()`, `attacksUnblocked()`, `dealsCombatDamageToPlayer()`, `creatureYouControlDealsCombatDamageToPlayer()`, …; CR 508.1, 509.1, 510.2). A combat ability carries no trigger-only wrapper: a restriction on the creature is the trigger's filter (`Triggers.creatureYouControlAttacks().withFilter(p)`, `becomesBlocked().withFilter(p)` for the blocker; `CombatTrigger.watchKey()` drops it but for the same-name and goaded filters, whose collectors read them), the intervening "if" and the limit are `TriggerOptions`, "blocks" once each combat and "one or more creatures deal combat damage" are `TriggerMultiplicity.ONE_OR_MORE` and "becomes blocked by a creature" is `EACH_BLOCKER` (CR 509.3a, 509.3d), and "attacks or blocks" is one ability with both triggers (`Card.addTrigger(List.of(...), options, effects)`). A combat ability is matched by its `CombatTrigger` (`TriggerMatcher.combatCondition`, on the abilities `TriggerIndex` lists as the layers leave them, a registered one's by `TemporaryGlobalTriggeredAbility.ability()`), which gives its filter on the creature (the one the watch key drops); its limit is marked by `TriggeredAbility.limitKey()` on the source ("attacks for the first time each turn" is `ONCE_EACH_TURN`, judged by the attack count) and its multiplicity judged by the matcher; the ally combat damage matchers record the creature that dealt the damage as the stack entry's triggering permanent (its creatures as the triggering permanents for "one or more"), which "it" / "that creature" reads. The collectors judge the intervening "if" and the event condition from the ability as it triggers (`ConditionEvaluationService.triggerConditionsMet`, or a `TriggerJudge` on the abilities a reader flattens), in the context of their event; the intervening "if" also wraps each effect as the `ConditionalEffect` that checks it again as it resolves, and the event condition is never checked again; code that only inspects an ability's effects reads `WatchedAbilities.rawEffects`. A multiplicity no combat collector reads ("one or more" on an attack, "each blocker" off "becomes blocked", "each source" off a damage trigger) is rejected as the `TriggeredAbility` is built. Each combat ability is one object on the stack (CR 603.3): `AttackTriggers`, `BlockTriggers` and `CombatDamageTriggers` put each ability, printed, granted or temporary, on the stack as one object of all its effects, and the attached-permanent matcher one object per ability; there is no trigger mode. On an Aura or Equipment the `THIS` attack, block, becomes-blocked and combat-damage-to-a-player triggers are the attached creature's, as the slots were. Damage triggers, combat or noncombat, have a real `DamageTrigger` (a `DamageEvent`: deals damage, to a player, opponent, you, creature or planeswalker, noncombat, an instant or sorcery's, one or more creatures'; is dealt damage, noncombat or excess damage (CR 120.10); you, an opponent or enchanted player is dealt damage; damage to you is prevented (CR 615.1); and an `ObjectRelation` for the source, or for the damaged permanent of an "is dealt damage" event), built by named factories (`Triggers.dealsDamage()`, `dealsDamageToPlayer()`, `dealtDamage()`, `enchantedCreatureDealtDamage()`, `creatureYouControlDealsDamageToCreature()`, `youAreDealtDamage()`, `sourceYouControlDealsDamageToOpponent()`, …; CR 120.1). Damage is a `DamageDealtEvent` or a `CombatDamageStepEvent`, matched by `DamageTriggers` and `CombatDamageTriggers` (see the damage events below). A damage ability carries no trigger-only wrapper: a restriction on the permanent is the trigger's filter (`Triggers.permanentYouControlDealtDamage().withFilter(p)`: the damaged permanent for an "is dealt damage" event and for "this deals damage", the dealer for the other "deals damage" events; `DamageTrigger.watchKey()` drops it), the intervening "if" and the limit are `TriggerOptions` (with `TriggerLimit.ONCE_EACH_TURN_FOR_EACH_CREATURE` for Stensia), "whenever a source deals damage to this" is `TriggerMultiplicity.EACH_SOURCE` (CR 603.2c), and one Oracle ability over several damage watches is one ability with all their triggers. A damage ability has no legacy view: `DamageTriggers` and `CombatDamageTriggers`, for printed, granted, persistent, graveyard, planar and registered abilities alike, read it from the ability (`TriggerMatcher.damageCondition`), judging the filter against its own permanent (the source, each dealer, the damaged permanent) with the watcher as the ability's source, the limit by `TriggeredAbility.limitKey()` (or for the plane and the creature, Stensia), and "each source" by splitting the event per source; the intervening "if" is judged from the ability as the dispatch reads it, with the damage dealt. The self-deals-damage snapshots (`PendingSourceDamage`, `CombatDamageState`) hold the abilities, not effects. On an Aura or Equipment the `THIS` deals-damage-to-a-player and to-an-opponent triggers are the attached creature's, as the slots were. Counter triggers have a real `CounterTrigger` (a `CounterEvent`: counters, +1/+1, -1/-1, loyalty, time or lore counters put or removed, by anyone or by you or an opponent, once per permanent or once per counter; becomes renowned or monstrous, evolves, trains, a Class reaches level 2 or 3, you get energy, you proliferate; an `ObjectRelation` for the permanent the counters are put on or removed from; and a filter for its type: a creature, a Human, a Hero, a non-Hydra creature, a planeswalker, a Saga), built by named factories (`Triggers.countersPutOnThis()`, `plusOneCountersPutOnThis()`, `plusOneCountersPutOnCreatureYouControl()`, `youPutCountersOnCreature()`, `minusOneCountersPutOnCreature()`, `becomesMonstrous()`, `youProliferate()`, …; CR 122.1, counters a permanent enters with included, CR 122.6). `timeCounterRemovedFromThisInExile()` functions from exile by default. Counters put or removed and the counter keyword actions are a `CounterChangeEvent`, emitted where they happen (`PermanentCounterSupport`, the train, evolve and Class-level handlers) and matched by `CounterTriggers`. A counter ability carries no trigger-only wrapper: a further restriction on the permanent is the trigger's filter (`CounterTrigger.withFilter(p)`, its `qualifier`), the intervening "if" and the limit are `TriggerOptions`, and the "you put counters on a creature you control", "you put +1/+1 counters on this", "you remove a time counter from this card while it's exiled" and "a +1/+1 counter is put on this" (each counter) events are read by the collectors of the event about any player (`CounterTrigger.watchedEvent()`, part of `watchKey()`). A counter ability has no legacy view : `CounterTriggers`, for printed, granted (Danny Pink), graveyard and exiled abilities alike, reads it with its ability's filter on the permanent (the `qualifier`), its own event (`byController()` for "you put" / "you remove", `eachCounter()` for "a +1/+1 counter is put on this", once for each counter) and its limit, judged and marked by `TriggeredAbility.limitKey()` on the source (or for the source and the creature, `ONCE_EACH_TURN_FOR_EACH_CREATURE`; "do this only once each turn" marked as the action is taken); the strict `printedEffects` / `effects` / `registrations` serve the collectors that judge none of them and throw on one, and the collectors reached through `dispatchWatch` (energy, proliferate, counters removed, time and lore counters put) judge only the limit. The collectors judge the event condition from the ability as it triggers, in the context of their event, and hand it to the stack door (`putTargetAbility`), which judges the intervening "if" and the limit and wraps the effects for the check as it resolves; the event condition is never checked again. A multiplicity other than once for each event is rejected as the `TriggeredAbility` is built. The "becomes monstrous" and exiled time-counter collectors hand their handlers every effect they read in the trigger context, put on the stack as one object. Becomes-the-target triggers have a real `TargetTrigger` (a `TargetEvent`: becomes the target of a spell, an Aura spell, an instant or sorcery spell, an opponent's spell, a spell or ability, an opponent's spell or ability (ward, CR 702.21a), your spell or ability, an activated ability (one or more, once per ability) or a backup ability; you, or you or a permanent you control, become the target; a player chooses targets; an `ObjectRelation` for the permanent that becomes the target; and a filter for its type), built by named factories (`Triggers.becomesTargetOfSpell()`, `becomesTargetOfSpellOrAbility()`, `becomesTargetOfOpponentSpellOrAbility()`, `creatureYouControlBecomesTargetOfOpponentSpellOrAbility()`, `youBecomeTargetOfSpell()`, `playerChoosesTargets()`, …; CR 601.2c, 602.2b). Becoming the target and choosing targets are a `TargetEvent`, matched by `TargetTriggers`, which still reads each watcher's abilities as the old collectors did (printed through `WatchedAbilities.printed`, granted for a duration, statically granted), not yet as the layers leave them. A becomes-the-target ability carries no trigger-only wrapper: a restriction on the permanent is the trigger's filter (`TargetTrigger.withFilter(p)`, its `qualifier`), the intervening "if" and the limit are `TriggerOptions`, and "this becomes the target of a spell [or ability] you control" (`becomesTargetOfYourSpell()`, `becomesTargetOfYourSpellOrAbility()`) and "a player or permanent becomes the target of an ability you control" (`playerOrPermanentBecomesTargetOfYourAbility()`) are read by the collectors of the event about anyone (`TargetTrigger.watchedEvent()`, part of `watchKey()`). A becomes-the-target ability has no legacy view : `TargetTriggers`, for printed abilities, abilities granted to the permanent (`WatchedAbilities.temporary` / `persistent`) and abilities a static ability grants (`GrantedTriggeredAbilitySupport.grantedWatchedAbilities`) alike, reads it with its ability's filter on the permanent (the `qualifier`, judged by the collector against the targeted permanent), its own event (`byController()` for "a spell [or ability] you control" and "an ability you control") and its limit ("triggers only once each turn", "for the first time each turn", judged and marked by `TriggeredAbility.limitKey()` on the source); the strict `printedEffects` / `effects` / `grantedToPermanentEffects` serve the collectors that judge none of them and throw on one. The collectors judge the intervening "if" and the event condition from the ability as it triggers (`ConditionEvaluationService.triggerConditionsMet`, or a `TriggerJudge` on the abilities a reader flattens), in the context of their event; the intervening "if" also wraps each effect as the `ConditionalEffect` that checks it again as it resolves, and the event condition is never checked again. "One or more" is rejected as the `TriggeredAbility` is built. "Of a spell or ability an opponent controls" on this permanent is ward's trigger whatever its effect: the non-counter collector reads the abilities granted to the permanent too. On an Aura or Equipment the `THIS` becomes-the-target-of-a-spell, Aura spell, spell or ability and opponent's spell or ability triggers are the attached permanent's, as the slots were. Draw, discard, cycle, scry, surveil, library search and shuffle triggers have a real `LibraryTrigger` (a `LibraryEvent`: draws a card, draws one except the first of their draw step, draws the first of their draw step, enchanted player draws, discards a card, an opponent causes them to discard a card, discards one or more cards at once, cycles a card, this card is cycled or discarded, scries, surveils, searches their own library, shuffles, a spell or ability causes its controller to shuffle; and a `PlayerRelation` for who does it, or for "this card is discarded" who controls the spell or ability that causes it), built by named factories (`Triggers.youDrawCard()`, `opponentDrawsCard()`, `youDiscardCard()`, `youCycleThisCard()`, `opponentCausesYouToDiscardThisCard()`, `youScry()`, `youSurveil()`, `opponentSearchesTheirLibrary()`, …; CR 121.1, 701.9a, 701.22a, 701.25a). A "this card is cycled or discarded" trigger functions from the zones the card can wind up in (CR 702.29c). They aren't rules events either: `DrawService`, the discard, cycle, scry and surveil collectors in `TriggerCollectionService`, `LibrarySearchTriggerHelper` and `LibraryShuffleHelper` still run where the slots were collected, reading the abilities through `LibraryWatch` (a `TriggerWatch`, one constant per old slot), and hand each ability to the stack door. No collector rebuilds an effect with the granting permanent bound in.

A damage-to-a-player trigger's "that player" — "target creature that player controls", "destroy target land that player controls" — is the player the event was about, never bound into the effect (the damage-to-a-player collectors' record, `TriggerCollectionService.playerDamageRecord`, names the damage, the player, the source and its controller whatever the effects are, the player also as the attacked target a "that player controls" target is judged against; for "a source an opponent controls deals damage to you" the non-targeting "that player" is that opponent): the door's `PermanentChoiceContext.AttackTriggerTarget` carries that player from the record, `TriggerTargetCollector` puts it in the filter context (`FilterContext.triggeringPlayerId`) that `PermanentControlledByTriggeringPlayerPredicate` reads, and the stack entry built from the choice keeps it (`StackEntry.triggeringPlayerId`) for the resolution recheck (`TargetLegalityService`, `TargetValidationContext.triggeringPlayerId`). Every damage-to-a-player collector (the combat damage service's own, attached, curse, ally and equipped readers, the noncombat `putDealsDamageToPlayerAbility`) records the event the same way whatever the effects are: the player dealt damage as the entry's triggering player and, when no target is chosen, its non-targeting `targetId`, the damage as its event value, and on an Aura's, Equipment's or Curse's ability the creature that dealt it as its triggering permanent (the ability's source stays the Aura or Equipment). A player-targeting effect the card declares no `target(...)` for is "that player" (a card printing "target opponent" declares it: Brash Taunter, Daredevil, Fearless Fighter); the triggered modal, its modes chosen as it is put on the stack or as it resolves, and the reflexive "when you do" abilities (`QueueReflexiveAbilityEffect`, `RemoveCounterFromSourceThenEffect`) reuse the entry's player by the same rule. No effect tells the collectors what to record (the `CombatDamageTriggerContextEffect` interface is gone). "Of that player's choice" on a combat damage trigger is the card's `combatTriggerTargetChosenByDefendingPlayer`. A reflexive "when you do" ability's "that player" (Dokuchi Silencer, CR 603.12) is the triggering player of the entry that created it: the combat damage collector gives a non-targeted "you may" entry the player dealt damage, `DiscardCardThenEffectHandler` gives its `DiscardFollowUp` the entry's triggering player (`withTriggeringPlayer`), the reflexive target is chosen and validated with it (the filter context, `TargetLegalityService.validateActivatedAbilityTargeting`'s triggering-player overload) and its `PermanentChoiceContext.MayAbilityTriggerTarget` (`withTriggeringPlayer`) gives it to the reflexive entry. A `SpellTargetTriggerAnyTarget` with a triggering player judges its target filter with it (Chandra's Incinerator's "that player controls" on noncombat damage to an opponent). A linked ability's "the exiled card" (Hoarding Dragon, CR 607.2a) is the stack entry's linked exiled card (`StackEntry.linkedExiledCardId`), set by the death collector from the source's imprint as the ability triggers, so the source returning and exiling another card can't redirect it. A death trigger's "another target card" is judged against the source's own physical card (its snapshot's original card), so a copy excludes itself rather than the card it copied. A discard trigger's "they" and "that card" (Gutmorn, Pactbound Servant) are the discarding player and the card discarded, which the discard default records on its entry (`StackEntry.triggeringPlayerId`, `setTriggeringCards`); the land-play default records the land played as the triggering card the same way.

A damage-to-a-permanent trigger records its event the same way whatever the effects are: "whenever this is dealt damage" (and "… noncombat damage"; `DamageTriggers.collectDealtDamageAbilities`) the damage as its event value (and X), the source of the damage as its triggering permanent with that source's controller as it dealt the damage, and the damaged permanent's last known information with its damage keywords as its source snapshot; "whenever a [filtered] creature is dealt damage", "a permanent you control is dealt damage" and "a source you control deals noncombat damage to a creature" (`damagedPermanentRecord`) the damaged permanent as the triggering permanent with its controller and last known information, and the damage; every one is handed to the stack door, which chooses a target as it goes on the stack. "That permanent or player" of a recipient ability (Ghyrson Starn) is the record's non-targeting target, dealt damage by `DealDamageToAnyTargetEffect.toEventObject`, which targets nothing; a declared "any target other than that permanent" (Toralf) reads `PermanentIsTriggeringPermanentPredicate`. The combat damage step reads its "is dealt damage" abilities as the damage is dealt and puts them on the stack, once its creatures have died, through the same default (`DamageTriggers.collectDealtDamageAbilities`, with the damaged permanent's last known information in `TriggerContext.DamageToCreature.damagedLastKnown`), so the limits, intervening "if"s, event conditions and additional-trigger effects (Roaming Throne) apply alike; the event conditions see the source as the triggering permanent and its controller as "that player" (Archfiend of Spite's "a source an opponent controls" is `NotCondition(TargetPlayerIsController())`). Damage of 0 isn't dealt and triggers nothing (CR 120.8).

A block or "becomes blocked by a creature" trigger's "that creature" — the creature on the other side of the block — is never chosen by the effect's class: `BlockTriggers` (the blocker's own declared and effect-made blocks, the "becomes blocked by a creature" abilities with `EACH_BLOCKER` or a filter on the blocker, and the Aura and Equipment abilities) records it on the entry whatever the effects are: as its triggering permanent (id, controller, last-known copy) and non-targeting `targetId`, with its power and toughness as the ability triggered (an Aura's or Equipment's entry keeps the enchanted or equipped creature as its triggering permanent and the other creature as its `targetId`). A permanent or player target the card declares (`target(...)`, Elite Javelineer) is chosen as the ability goes on the stack; one it doesn't declare is that creature (CR 115.10a). A "[filter] creature" is the trigger's filter (`Triggers.blocks().withFilter`, `Triggers.becomesBlocked().withFilter`), judged as the creature blocks or becomes blocked (CR 509.3f): on the creature it blocks, or with `ONE_OR_MORE` any creature it blocks; for each blocker with `EACH_BLOCKER`, and without it ("becomes blocked by one or more") once if any blocker matches. No effect tells the collectors to do this (the `CombatOpponentReferencingEffect` interface is gone). A "whenever a [filter] creature (you control) becomes blocked" watcher (`CombatBlockService`'s ally and any-creature readers) is the ability's source (CR 113.7) and records the blocked creature as its triggering permanent (id, controller, a last-known copy) and non-targeting target whatever the effects are, so "it" is a triggering-permanent reference, never a self effect with a rebound source; "becomes blocked by a creature" there (`EACH_BLOCKER`, No Quarter, Righteous Indignation) is once per declared pair, the blocker its target and the pair's comparison its event condition. A "whenever you attack" entry records its attacking creatures whatever the effects are (the band's for `TriggerMultiplicity.EACH_BAND`), and "they gain …" is `GrantScope.DECLARED_ATTACKERS`; an Equipment's own "whenever equipped creature attacks, choose one" (Pip-Boy 3000) is its controller's, an ability granted to the creature its controller's (CR 113.8).

**Step and phase events.** A step or phase beginning is a `StepEvent` (moment, active player; the turn's second main phase is an event of its own), which `StepTriggerService.beginStep` emits as an occurrence of its own (CR 603.2b, 603.2c) and the pipeline matches at once: `TriggerIndex.stepCandidates` lists the face-up planar objects' abilities (controlled by the planar controller, CR 901.6), the emblems' (CR 114.4), and, per player in APNAP order, their permanents' and face-up schemes' (as the layers leave them: `TriggerIndex.permanentAbilities`, no card ability for a face-down permanent or one that lost them, CR 708.2; static grants and granted cumulative upkeep included), their command-zone, graveyard and exile cards' abilities that function there (CR 113.6; an exiled card's "each upkeep" only while it is suspended), and at upkeep the active player's exiled cards' egg, refine and suspend counter abilities (`StepCandidate.ExileCounterAbility`, put just below the exile abilities); `TriggerMatcher.matchedStep` relates the active player to the ability (your, each, each opponent's, the chosen player's, the enchanted player's, the enchanted permanent's controller's), and an ability triggers once however many of its conditions the step meets. `RulesEventPipeline.triggerStep` orders the matches by `StepMatch.StepGroup` (per moment, `STEP_ORDER`; the precombat-main reader puts a permanent's own abilities last-first, its controller's order, CR 603.3b), judges each event condition (a step ability has no multiplicity or limit but "only once") and hands it to the stack door with the step's record (`stepRecord`): the active player; a permanent source as it was and what it is attached to (`attachedPermanentSnapshot`, CR 608.2h); a graveyard source's stay and triggering card (CR 400.7); "that player" for an each, opponent's, chosen player's, Curse's or emblem ability, the player whose step it is (the enchanted player for a Curse's), as the triggering player and non-targeting `targetId` (CR 115.10a), which the event condition reads too (Razor Pendulum); an Aura's ability that acts on the enchanted permanent's controller names that permanent and its controller (the player at upkeep and draw step, the permanent at end step); "at end of combat" names no object. A player target the card doesn't declare is that player (Pillar Tombs of Aku); a declared one is chosen. An ability an Aura grants is the permanent's own (CR 113.8): the door stamps the granting permanent and the ability's own target filter (Custody Battle). Each step handler ends with `beginNextStepTriggerChoice`, which begins the door's queued mode and target choices before anyone gets priority; a test that triggers abilities by calling a service directly begins them with `GameTestHarness.beginTriggerChoices()`. The delayed and engine-made step abilities (echo, the initiative, rad counters, boons, opening-hand reveals, suspended spells' delay counters, `DelayedAction` drains) are put on the stack by `StepTriggerService` before or after the step's event.

Every watch's collector hands the registry one triggered ability: `TriggerCollectorRegistry.dispatch(match, watch, context)` takes a `TriggerMatchContext` whose `effects()` are the ability's effects in order, as its reader read them (an intervening "if" wrapped around each), and the watch's handler puts that ability on the stack as one object (CR 603.3): to its target choice with every effect (`match.admits(kind)`, `match.targetingEffect()` for the target group and filter, `match.targetIsOptional()`), else one entry of `match.stackEffects()` with the watch's record; a modal ability is its "choose one" alone (`match.modal(...)`, which fails loudly beside other effects). A watch's default is `(TriggerMatchContext, TriggerContext)` registered for `CardEffect.class`; a handler registered for an effect class takes `(TriggerMatchContext, <that class>, TriggerContext)` and routes an ability that has an effect of exactly that class (`TriggerCollectorRegistry.handlerOf` enforces both shapes). The generic collectors of `TriggerCollectionService` (`dispatchRegistrations`, `triggerZoneChange`, `triggerEntry`, `triggerTokensEnter`, the `dispatch{Counter,Saga,Action,Misc,Library}Ability` readers, the creature-death and mutate collectors, the planar readers) dispatch each ability once (`byAbility`); none dispatches an effect alone or joins a permanent's abilities. The collectors outside the registry read the same way, one list per ability (`LibraryAbilityReader.printedEffectsByAbility`, `ActionAbilityReader.printedEffectsByAbility`, `MiscAbilityReader.printedEffectsByAbility` / `effectsByAbility`): the library search and shuffle helpers, "a player loses the game", the championed collector, and `TriggerCollectionService`'s self-cycled, self-discarded, graveyard, monarch, Case, crew, saddle, exploit, clash, plot, Aura- and Equipment-attached, control-change, enters-causes-a-trigger, creature-death and planar collectors; each puts one ability on the stack as one object of its effects (a lone "you may" of the graveyard and graveyard creature-death collectors goes on the stack the same way as any other ability, with the same record, and is asked as it resolves, CR 603.5). A hand-rolled collector judges an ability's filter, limit, conditions and "one or more" once, from the ability's first read, and decides how it goes on the stack from all its effects: to its target choice with every effect when one of them has a target (CR 603.3d), aimed at "that spell or ability" when one acts only on a spell (`actsOnASpell(List)`, ward), else one entry. A "one or more" mark of a collector called once per occurrence (combat damage to you, to an opponent, a plane's, the excess noncombat damage one) is keyed by the ability's place among the source's abilities of the watch, never by its first effect or by the source alone. "You or a permanent you control becomes the target" triggers once for each such target; the "you and/or at least one permanent you control" wording is `TriggerOptions.ONE_OR_MORE` on that trigger (Leyline of Combustion), the one becomes-the-target condition `TriggeredAbility` admits it for. A "one or more" enters ability joined by a later permanent of the same event (`RulesEventPipeline.triggerEnteringObservers`) is keyed by the whole ability (`GameData.simultaneousCreatureEntryTriggers`) and joins only that ability's stack object. The zone-change collectors `triggerZoneChange`, `triggerEntry` and `triggerPermanentChange` write by hand (another permanent, creature or artifact leaves, the returned-to-hand, exiled and leaves-without-dying ones, enters from a graveyard or from exile, phases in or out, the suspended card's cast ability, and every ability that triggers from a graveyard: land and creature enters, land put into a graveyard, milled, leaves a graveyard, sacrificed, turned face up, `enqueueGraveyardAbility` / `enqueueGraveyardEnterAbility`) do the same: one entry of the ability's effects, a "you may" among them like any other effect, or one target choice with every effect when one of them targets. **Attack and block events.** A declaration of attackers is an `AttackEvent` (the attackers in declaration order, what each attacks, each as declared, the creatures they enlisted), emitted by `CombatAttackService.finishAttackerDeclaration` after the keyword attack abilities (decayed, melee, battle cry, dethrone, training, double team) and matched by `AttackTriggers`; a declaration of blockers, a block an effect makes, a creature entering the battlefield blocking and an attacker an effect makes blocked are a `BlockEvent` of that `Kind`, emitted by `CombatBlockService` and matched by `BlockTriggers`, the flanking and delayed block abilities after it (CR 508.3a, 509.3). Each reads its candidates as the layers leave them (`TriggerIndex.permanentAbilities`, `graveyardAbilities`, `cardAbilities`; the planes', emblems' and delayed `TemporaryGlobalTriggeredAbility`s) and matches an ability by its combat trigger condition (`TriggerMatcher.combatCondition`, the event and relation its `watchKey()` names, with its filter), judges the filter, multiplicity ("blocks" once each combat is `ONE_OR_MORE`, CR 509.3a; "becomes blocked by a creature" is `EACH_BLOCKER`, once for each blocker, CR 509.3d; "in a band" `EACH_BAND`) and event condition, and records the event whatever the effects are (an attack: the attacked target, the defending player, the number of attackers as X, the declared attackers' snapshots; "that creature" or "that player" as the non-targeting target); the door judges the limit and intervening "if" and reads the route from the effects. An attack ability its source's attack caused is `causedBySourceAttacking()`, which the door hands to `AttackTriggers.triggerAttackingSourceAbility` (Firebender Ascension). **Damage events.** Damage a spell, ability or fight deals is a `DamageDealtEvent` (`ToPermanent`, `ToPlayer`, `DealtByCreature`, `PreventedToPlayer`; `SourcesDealtDamage` as a resolution's noncombat damage is totalled; `CombatToPermanent`, `CombatToPlayer`, `CombatToCreature` as a combat damage step's damage is applied), and a combat damage step is a `CombatDamageStepEvent` in two stages, `DEALT` before state-based actions and `AFTER_STATE_BASED_ACTIONS`. Each is emitted as an occurrence of its own where its collectors ran and matched by `DamageTriggers` and `CombatDamageTriggers` (`TriggerMatcher.damageCondition`, `combatCondition`). A live permanent's damage abilities are the ones it has as the layers leave it (`DamageTriggers.abilities`: `TriggerIndex.permanentAbilities`, its card's own abilities through their text changes; `TriggerIndex.graveyardAbilities` for a graveyard card), so a face-down or ability-less permanent's card abilities don't trigger (CR 708.2, 613.1f). A source or watcher that may have left the battlefield before its ability is put (a combat-damage dealer, a departed ally watcher, an Equipment, a snapshotted self ability) is still read as it last existed. The abilities that wait out state-based actions are held in `CombatDamageState` and put on the stack where they were. Exert's "you may exert" is asked as attackers are declared: it is no ability. The enchanted-creature unblocked readers name the Aura as the source (CR 113.7) and the enchanted attacker as the triggering permanent, which Cloak of Confusion's and Farrel's Mantle's effects read (`AssignNoCombatDamageEffect.ofTriggeringPermanent`, `DealDamageToTargetCreatureEffect.byTriggeringPermanent`: the attacker deals the damage, CR 608.2h). The "one or more creatures you control deal combat damage" mark is keyed by the ability's place among its source's abilities of the watch, and a limit is marked whichever way the ability reaches the stack. Nothing is dropped or recorded by an effect's class: renown's "if it isn't renowned" and Semblance Scanner's "if it's not a token" are the cards' intervening "if"s (judged with the creature that dealt the damage as the triggering permanent), a target the effect declares as chosen at random (`CardEffect.targetChosenAtRandom()` with a declared graveyard target, Power Pack) is picked as the ability goes on the stack with every effect of the ability, and "when that creature deals combat damage to a player this turn" is a delayed triggered ability the card registers (Optimus Prime, Autobot Leader), not a granted ability told apart by its effect. `scripts/step15-run17z14c-scan.py` lists the flat reads left anywhere and `scripts/step15-run17z14d-scan.py` the per-effect loops; run 17z14g's Findings classify each.

**Counter, tap and life events.** Counters put on or removed from a permanent, player or exiled card and the counter keyword actions (proliferate, renown, monstrosity, training, evolve, a Class level, {E}) are a `CounterChangeEvent` of that `Kind`. Tapping, untapping, the untap step's untaps, a teamwork tap and a tap for mana (CR 106.12) are a `TapEvent`. Gaining, losing or paying life is a `LifeEvent`; paying is a loss too (CR 119.4) and an event of its own. Each is emitted as an occurrence of its own where its collector ran (`RulesEventLog.occur`): `PermanentCounterSupport`'s emitters, which keep the turn's counter bookkeeping first, the keyword handlers, `TapUntapSupport` and the tap costs, the mana-ability paths, and `LifeSupport.lifeLost` / `lifePaid` / the gains, which keep "life lost this turn" and speed's inherent ability (CR 702.179d). `CounterTriggers`, `TapTriggers` and `LifeTriggers` match them. Abilities come from `TriggerIndex.permanentAbilities` (text changes, CR 612.1; grants; no card abilities face down, CR 708.2), `graveyardAbilities` and `cardAbilities`, matched by `watchKey()`. The matcher judges filter, relation, "you put", "first time" and "one or more"; the door judges the limit and intervening "if". Records are kept whatever the effects are: life gives "that player" and the amount as `eventValue`; tap gives the tapped permanent and its controller (`TRIGGERING_PERMANENT_CONTROLLER` recipients read it), "one or more" checked against `beginPermanentTapTriggerBatch`; counters give `eventRecord` / `countersPutRecord`, and "once each turn for each creature" is judged by the door by the creature the event names (`TriggeredAbilityRequest.withLimitCreature`). A triggered mana ability (CR 605.1b) resolves at once (`putManaAbility`, CR 605.4a) or waits for the mana choice (`holdForProducedMana`; `TapTriggers.putResolvedProducedManaTrigger`). `TriggerCollectorRegistry.register` throws on a second handler for one (watch, effect class) key. The library, player and keyword action, misc and Saga watches hand each ability to the stack door with one record, `TriggerCollectionService.familyRecord`: the player the event was about as triggering player (an opponent also as the non-targeting "that player": a discard's, scry's, surveil's, tax payment's or control gain's), the count as `eventValue`, the permanent the event was about, the cards it was about with their graveyard stays, the source snapshot, whatever the effects are; the door chooses the targets. Their collectors judge only what the ability's trigger reads (`familyEventMatches`: the discarded or action card's filter, the first time each turn, a door, the crewing creature, the scheme's or Saga's controller, a Ring-bearer other than the source). A "whenever [a player] casts a spell" ability without a spell filter is read as `SpellFilter.ANY` by the battlefield and exile cast readers (`TriggerCollectionService.collectedSpellFilter`), so the generic cast collector records the spell whatever the effects are; no class-keyed handler of a cast watch is left. An enchanted-tap "choose one" (Relic Bind) goes to the stack door with the same record as any other tap ability, its mode announced from the stack by `StackedModalTriggerService`; a player-only mode that chooses its target declares a `PlayerPredicateTargetFilter`, which keeps it from being read as the entry's non-targeting "that player".

No collector judges or records an ability by the class of one of its effects where a card can say it. An intervening "if" is the ability's (`TriggerOptions.withInterveningIf`), judged by the collector as the ability triggers and by the `ConditionalEffect` its reader wraps around the effects as it resolves: `SourceDealtDamageToTargetPlayerThisTurn` (Vessel of the All-Consuming, judged by the noncombat and the combat damage collectors against the damaged player), `TargetPlayerAttackedBySubtypeControllerControlledThisTurn` (Ramses; `GameOutcomeService` judges the loses-the-game abilities against the player who lost), `TriggeringSpellMatches(StackEntryIsSingleTargetPredicate)` (Grip of Chaos; `checkTargetChoiceTriggers` judges it on the spell or ability whose targets were chosen and records that as the entry's triggering spell), `NotCondition(TriggeringPermanentHasSubtype(KREE))` (Captain Marvel). The Pandorica's untap ability has the event condition `SourceKeepsPermanentPhasedOut`. A counter-placement entry of `PermanentCounterSupport` ("you put counters on another creature", "an opponent puts counters on a creature they control") records the creature as its triggering permanent, the player who put the counters as its triggering player, the kind as `StackEntry.eventCounterType` and the number as its event value, whatever its effects are; `PutSameCountersOnSourceEffect` reads them. "When you remove the last [kind] counter from this" is `Triggers.youRemoveLastCounterFromThis(kind)` (a `CounterTrigger` with a `counterKind`, which `watchKey()` drops and `CounterTriggers` reads from the trigger, `PermanentCounterSupport.notifyLastCounterRemoved`). An "enchanted permanent is put into a graveyard" entry is marked `awaitingSourceGraveyardEntry`, and `GameData.markGraveyardEntry` records the Aura's graveyard stay on it as the Aura follows (CR 704.5m, CR 400.7), whatever its effects are; "it deals damage to its controller" (`DealDamageToEnchantedPermanentControllerEffect.dealtByEnchantedPermanent`) takes its damage source from the entry's triggering permanent as it resolves. The generic cast collector puts an ability that chooses no target on the stack one way: the caster as its non-targeting player and the spell as its triggering card and spell; an effect that acts on "that spell" without a spell target spec reads the triggering card, and "enchanted creature" of an Aura's ability is the source's or its snapshot's attachment (`CounterSpellingEffect.targetsTriggeringSpell` and the collector's `AttachedPermanentSelfTargetingEffect` branch are gone). The sacrifice default sends any ability with a graveyard target to its choice (`TriggerMatchContext.admits(GRAVEYARD_CARD)`).

**The stack door.** `TriggeredAbilityStackService.put(gameData, TriggeredAbilityRequest)` is the one way a collector puts a triggered ability on the stack; the trigger pipeline's step, attack and block matchers use it (`RulesEventPipeline.triggerStep`, `AttackTriggers`, `BlockTriggers`), and so do the damage and combat-damage matchers (`DamageTriggers`, `CombatDamageTriggers`), the spell, activation and becomes-the-target matchers (`SpellTriggers`, `TargetTriggers`), the counter, tap and life matchers (`CounterTriggers`, `TapTriggers`, `LifeTriggers`), `PlanechaseService.trigger`, "an ability of an attacking creature you control triggers" (Firebender Ascension), the library, draw, discard, player and keyword action, misc and Saga collectors (`TriggerCollectionService.putFamilyAbilities` / `putFamilyAbility` / `putJudgedFamilyAbility` with `familyRecord`, which stamps the event of the `TriggerContext` whatever the effects are; `putGraveyardFamilyAbilities` for a graveyard card's, naming that graveyard incarnation as the source; `DrawService.putDrawAbility`, whose `TriggerContext.Draw` event lets the draw-only "triggers an additional time" effects count; `DiscardRecords.record`; the cycled, discarded, plotted and exploiting card's own abilities, the control-change, Aura and Equipment attach and unattach, monarch, clash, coin flip, Case, champion, "a permanent entering causes an ability to trigger", "whenever a player loses the game" and Saga chapter abilities that choose nothing or announce a mode); so do a permanent's own enters abilities, the tap-for-mana, library search and shuffle, face-up, transform and zone-change collectors, and every ability the engine makes for a keyword or a rule (see **Engine-made abilities**). Abilities that trigger as an activated ability's cost is paid (crew, saddle, station) are handed to the door inside `TriggerCollectionService.holdForActivation`, which moves what reached the stack to `GameData.pendingActivatedAbilityCostTriggers` until the ability is on the stack (CR 603.3). An effect "of an opponent's choice" (`CardEffect.targetChosenByAnOpponent`, Karplusan Minotaur) is parked as an `AttackTriggerTarget` with no chooser yet; its pump names the one opponent, or asks the controller which opponent chooses (`ChooseOpponentToChooseTriggerTarget`, wrapping that choice). The request is the ability whole, its source card and permanent, its controller, the stack entry's description, the context its intervening "if" is judged in, a `TriggerRecord` that stamps what the event was on the entry, whether creatures attacking caused it (`causedByAttack()`, and `causedBySourceAttacking()` when its source was one of them, CR 508.3a) and the event the "triggers an additional time" effects judge (`withEvent`, a combat damage event). The collector judges the trigger's filter, multiplicity and event condition (`ConditionEvaluationService.eventConditionMet`) and nothing else: it never reads, wraps or rebuilds `effects()` and never builds an entry. The door, in order: judges the intervening "if" and wraps each effect for resolution (CR 603.4; not a fact of the event, `EventFactCondition`: the attack as declared, Treasure mana spent to activate the ability, Vazi; not a mode chosen as it triggers, whose card writes the "if" into each mode: Jin Sakai; `TriggeringSpellMatches` is judged on the context's triggering spell), checks and marks the limit (CR 603.2h; "once each turn for each creature" by the request's `limitCreatureId`), counts the additional times it triggers (`countAdditionalTriggeredAbilityTriggers` with the attack flag and the event, one stack object each, CR 603.3); builds one entry of the effects as written (a "you may" stays and is asked on resolution, CR 603.5) with the granting permanent of a granted ability and whether its attacking source caused it (`StackEntry.isTriggeredBySourceAttacking`); stamps the record and aims an effect that acts only on a spell or ability at the record's triggering spell (non-targeting, CR 115.10a) unless the record names an object other than a player; hands it off; then routes it, asking the effects only through `CardEffect`: a mode chosen as it triggers (`modesChosenAsItTriggers`, CR 603.3c) parks it for its mode, with the record's attacked target and triggering permanent, "choose up to X" reading X as it goes on the stack from the stamped entry (`CardEffect.maximumModesChosenAsItTriggers`, Riku of Many Paths) and removing it with no mode to choose (CR 700.2b); the two-step counter move (`AttackCounterMoveEffect`, Decimator Beetle) parks it for its two choices, the second finishing it; a graveyard target chosen at random (`targetChosenAtRandom`, Power Pack) is picked now, the ability removed without one; a graveyard card target or choice (`targetSpec`, `graveyardCardChoice()`, which looks through a "you may" or an "if") parks it for one graveyard choice with the record's X, power and attackers, narrowed to "that player's graveyard" (an opponent's graveyard, or graveyard cards whose effect names none, of a record with a triggering player; a choice that says "defending player's graveyard", `GraveyardCardChoosingEffect.choosesFromEventPlayersGraveyard`), and up to the event's amount for a count that reads it (Froghemoth); a permanent, player or exiled-card target parks it for its target choice (CR 603.3d). An effect chooses a target unless the record names an object it could act on (a non-targeting `targetId` other than the source, or the source when it is also the record's triggering permanent: a lone attacking Noble Hierarch's own exalted) and the card doesn't declare the target with `target(...)`: the named object is "that creature" or "that player" (CR 115.10a) only for an effect that could target nothing but objects of its kind and type, so "any target" or "target player or planeswalker" beside "that creature" is chosen. Targets in two or more of the ability's groups (the groups bound to its effects, with a bare positional group belonging to the ability of the next bound group: Gimli's Reckless Might), a dynamic count, one "up to one" group (its controller is a legal player target, not a refusal) or an Aura's group after what it enchants (read by position, Super-Soldier Serum) are chosen group by group (`ETBTokenMultiTargetTrigger`); any other target in one choice (`AttackTriggerTarget`), the targets of one group of several announced together (CR 601.2c) under the card's constraint between them. The target is chosen by the defending player for a card whose combat ability says so (`isCombatTriggerTargetChosenByDefendingPlayer`, the record's triggering or else defending player), by the active player for an effect that says so (`targetChosenByActivePlayer`; a "you may" of `MayChoicePlayer.ACTIVE_PLAYER`: "that player may … target … of their choice"), else by its controller. An ability that chooses nothing goes to `GameData.enqueueTrigger` (ordering stays in `TriggeredAbilityQueueService`, CR 603.3b). The door also stamps the ability's own target filter (`TriggeredAbility.targetFilter()`) on the entry, which the target choice (`TriggeredAbilityQueueService.targetFilterOf`) and resolution read, and lets the active player choose a target whose filter says so (`TargetFilter.activePlayerChoosesTarget`). A "choose one" the stack can't announce (`StackedModalTriggerService.announcesMode` false: a graveyard target, "choose up to", "choose both instead") is announced as the ability goes on the stack, its `choicesMaxCondition` judged in the request's context; a mode chosen at random (`CardEffect.modesChosenAtRandomAsItTriggers`, Umaro, Raging Yeti) is picked among the modes that can be chosen and the ability removed without one (CR 603.3c); a permanent or player target chosen at random (`targetChosenAtRandom`, Witch Hunt, Furnace Layer) is picked among the legal ones (CR 603.3d). An effect bound to a group no other ability of the card has an effect bound to targets by position whatever kind it declares (`targetsOwnGroup`, Glen Elendra's exchange); an effect bound to an Aura's first group, what it enchants, declares no target (Strangling Grasp, Insubordination), and an Aura's bare group belongs to no ability; a bare group after the last bound group belongs to that group's ability (Iroh, Tea Master). A graveyard card beside other groups, or under the card's multi-target constraint (Orzhova), and an effect that divides among its targets as it goes on the stack (`CardEffect.dividesAmongTargetsAsItGoesOnTheStack`, Towashi) are walked group by group; one target that may be a permanent or a graveyard card (Taskmaster, Mercenary Mimic) is one choice offering both. An "up to one" group is walked only when it may target a player; a permanent-only one is one choice its controller declines by choosing themselves, and an "up to N" ability with no legal target goes on the stack with none. The target choice offers players as players (an any-target choice), filtered by the ability's player filter, and passes the record's triggering permanent and X to the collector; the group walk applies the effects' own declared restriction ("other target creature you control", Irma, Part-Time Mutant). A choice queued for a planar ability holds its record (`GameData.queuedTriggerRecord`), so a phenomenon isn't left while its ability waits for targets (`PlanechaseService.checkPhenomena`), and door choices copy their records for simulations. A parked entry is flagged (`StackEntry.isParkedAtStackDoor`) and travels as the choice's `triggerRecord`; the choice's handler finishes it through the one continuation, `finishParked(gameData, record, choice)`, which puts a new stack object of the record with the choice applied (the chosen modes' or the choice's effects, targets, a cleared optional target), runs the becomes-the-target and crime checks once it has a target (CR 700.13) and tells the "a creature you control attacking causes a triggered ability of that creature to trigger" watchers (Firebender Ascension) of an ability its still attacking source caused. The handlers that call it: the single and multi-target `AttackTriggerTarget` answers, the no-legal-target "up to one" branch of `processNextAttackTriggerTarget`, the no-target branch of `queueChosenTriggeredModalTrigger`, the group-by-group walk's last group (`ETBTokenTargetService`, for the record's own effects; `StackEntry.adoptChosenTargets`), and for a graveyard target (`SpellGraveyardTargetTrigger`, queued with the parked record) the triggered-ability answer of `GraveyardChoiceHandlerService`'s multi-graveyard choice (cards chosen from a narrowed graveyard name that player as the entry's target) and the "up to" none-to-choose branch of `TriggeredAbilityQueueService.pushSpellGraveyardTriggeredAbilityWithoutTargets`. After a mode is chosen, its attack-target choice is made before the next ability's mode (`ChoiceHandlerService`). Every choice made as an ability goes on the stack holds the parked record itself (not a copy, so what a departure stamps on it reaches the answer) and its answer finishes it through `finishParked`: a chosen mode's targets on the runtime card copy that declares them (`finishParked(gameData, record, card, ...)`, CR 603.3c), a division, the counter move, a second target judged against the first (`CardEffect.choosesSecondTargetAgainstFirst`, Puca's Mischief, Spawnbroker), a graveyard target. **Only the door builds a triggered entry.** `TriggeredAbilityStackService` is the one subclass of the domain's `StackDoor`, whose protected members build a triggered entry (`newTriggeredEntry`), release it to the stack (`enqueue`) and hand off a record (`handOff`); `GameData.enqueueTrigger` and `handOffTriggerRecord` are package-private to it. `StackEntry`'s public constructors refuse `TRIGGERED_ABILITY`, and the stack refuses a triggered entry the door didn't release and a carrier. An entry made from an existing stack object (a copy, CR 707.10, or the record a resolution hands another handler) is `StackEntry.derivedFrom(source, ...)`, which keeps the source's type and release; an entry that stands for an object in a resolution and never reaches the stack (the creature that deals damage, the resolving object a nested effect resolves for) is `StackEntry.carrier(...)`. Tests build released triggered entries through `TestStackDoor` (test fixtures). `TriggerStackDoorRatchetTest` (engine) fails when a main source file other than the door, `StackDoor`, `StackEntry` and `StackEntryType` names `TRIGGERED_ABILITY` as a value; ask "is it an ability" with `StackEntryType.isAbility`. The test fixtures' ledger (`MV_TRIGGER_LEDGER=<file>`, `TriggerLedger`) writes one line per triggered ability that reaches the stack, by role, for diffing a family's card tests before and after it moves; sort the lines and drop the per-test sequence numbers, since the order two players' abilities arrive in follows map order.

Every way an ability of one trigger reaches the stack records the same trigger event. A collector that hands an ability to a mode choice (CR 603.3c) or a target choice (CR 603.3d) builds the entry it would put on the stack for an ability that chooses nothing and gives it to the choice as its `triggerRecord` (`TriggeredModalTrigger`, `SpellGraveyardTargetTrigger`, `AttackTriggerTarget`, `EntersTriggerTarget`, `ETBSpellTargetTrigger`, the group-by-group walk `ETBTokenMultiTargetTrigger` (`withProgress` keeps it from step to step) and its `CounterDistributionAssignment` division, `GraveyardTargetOperationState`; `withTriggerRecord`), and the handler that builds the entry calls `StackEntry.carryTriggerRecord`: the trigger event (`copyTriggerEventFrom`), the source snapshot, how it was cast and the "do this only once each turn" mark. Don't hand-copy single fields into a choice context for a new route. Limits are the ability's own (run 17z15d): "triggers only once each turn", "triggers only once", the first-time and "one or more" marks and "do this only once each turn" are all kept under `TriggeredAbility.limitKey()` for the source (`GameData.keyedOncePerTurnTriggersFiredThisTurn` / `keyedOnceOnlyTriggersFired`); the last is marked as the action is taken, from the key the stack entry carries (`StackEntry.onceEachTurnActionKey`, `TriggeredAbilityStackService.markActionTaken`). Don't add a per-permanent limit set or flag. A graveyard choice that begins while another choice is awaiting input is queued as a `SpellGraveyardTargetTrigger` (the targeting service does it), never written over `GameData.graveyardTargetOperation`.

The trigger record is handed off, not threaded. A collector builds the entry of the ability that chooses nothing first and calls `GameData.handOffTriggerRecord(entry)` before it takes any route; that puts the entry in the game's one-shot hand. Whatever the ability goes through next takes it: `queueInteraction` / `queueInteractionFirst` keep it with the queued choice (`pollPendingInteraction` puts it back in hand), `InteractionState.beginInteraction` keeps it with the prompt (`InteractionHandlerRegistry.dispatchAnswer` puts it back in hand while the answer is handled), and the first `TRIGGERED_ABILITY` entry of the same source card that reaches `gameData.stack` or `enqueueTrigger` is given it (`StackEntry.carryTriggerRecord`: the trigger event, the source snapshot, how it was cast (its alternative cost, whether it was kicked, the optional and repeated costs paid, a promised gift), the once-each-turn key, the active player, a copied ability's copy flag, X and the non-targeting "that player" when the entry has none). Putting the handed-off entry itself on the stack empties the hand. So a mode (CR 603.3c), a target or a graveyard card (CR 603.3d) chosen as the ability goes on the stack records what the plain entry records without any choice type or handler passing it on: don't add a `triggerRecord` component to a new choice type, and don't copy event fields into a choice context or set them in a choice handler (the carry overwrites them with the collector's). `TriggerCollectorRegistry.dispatch` runs every registered handler inside `beginTriggerRouting` / `endTriggerRouting` (empty hand on entry, leftovers dropped on exit); a hand-rolled collector wraps one ability's routing in `GameData.routeTriggeredAbility`. Inside a routing, a choice queued or asked with nothing handed off is reported to `GameData.interactionWithoutTriggerRecord`, which `BaseCardTest` turns into a test failure; `StackResolutionService.resolveTopOfStack` and the end of every game action (`GameMutationCoordinator`) drop whatever is left in hand, so the record of an ability removed for want of a legal choice can't reach a later ability of the same card. A new collector route therefore needs only the hand-off; `TriggerRouteRecordTest` (application module) compares every route of a watch on every trigger factory of `Triggers` with the plain entry, field by field (run 17z17b): a new factory fails its `everyTriggerFactoryHasAWatchOrAReason` until it has a watch or a stated reason in `UNMEASURED`, and a pair that reaches no entry is in `EXCLUDED` with its reason. The plain entry carries the source's snapshot (`setSourcePermanentSnapshot`) and whatever the collector knows of the event (the player dealt damage, the targeted creature, the placed counters) before it is handed off, never only on the branch that queues a choice. A permanent that leaves the battlefield while an ability that names it is still choosing is stamped on the record as it is on a stack entry: `PermanentRemovalService` walks `GameData.stackEntriesAndTriggerRecords()` (the stack plus the record in hand and those kept with queued choices and prompts), and `StackEntry.carryTriggerRecord` hands the last-known maps on, so use that method, not `gameData.stack`, when stamping last-known information. A graveyard target choice is one operation per game (`GameData.graveyardTargetOperation`): a `GraveyardTargetingService` method that begins one for a triggered ability starts with `waitsForChoiceInProgress`, which queues the ability as a `SpellGraveyardTargetTrigger.deferring(...)` while another choice is being made and has the same call begin the choice when `processNextSpellGraveyardTargetTrigger` takes it out; never write the operation over a choice in progress. The fixtures' audit (`MV_TRIGGER_RECORD_AUDIT=<file>`, `BaseCardTest`) lists every choice begun with no record and every record that left the hand untaken (`GameData.triggerRecordLeftBehind`), with the engine frames. The older explicit `triggerRecord` components remain on eight choice types and are overridden by the hand when both exist. The entry takes the record's X when the choice set none, and the damage, sacrifice, cast and counters collectors no longer give a choice the event's value as its X (run 17z16b2): a target restricted by the event's value is chosen against the record and judged against the entry's event value. The choice's own stays for the mana value limit a graveyard target was chosen against (`graveyardTargetMaxManaValue`), and an ability of "up to one target" whose controller chose none is not given the record's non-targeting "that player" (`StackEntry.hasTargetToChoose`). The record of "when this enters" and "whenever this attacks" has no triggering permanent on any route: an effect that means the ability's own permanent by "it" falls back to the entry's source when the entry has none (`AttachTargetEquipmentToTriggeringPermanentEffectHandler`, `ExchangeControlOfTargetPermanentsEffectHandler`). A route's handler can't add event data the record lacks, since the carry overwrites it: put it on the record in the collector (the delayed end-step abilities' "that creature").

**Abilities a resolution makes.** A reflexive triggered ability ("when you do, ...", CR 603.12) and a delayed one (CR 603.7) go on the stack through the stack door, never by `stack.add`. The maker builds the ability's entry with `TriggeredAbilityStackService.madeAbility(...)` (the door's factory; a reflexive ability's from the resolving entry: `ReflexiveAbilitySupport.record(gameData, resolvingEntry, effects)` copies its card, controller and source, X, whole trigger event (`StackEntry.copyTriggerEventFrom`), source snapshot, active player and alternative cost, and the player it was about as the non-targeting "that player"; `recordFor` and `resolvingEntryOf` do the same for a choice handler's follow-up), stamps on it what the ability needs that the resolving entry lacks (the times a cost was paid as its X, the permanent sacrificed, a target filter of its own), and hands it to `putMade` (reflexive) or `putDelayed` (delayed). The door marks it `StackEntry.madeByResolution` and routes it as `put` routes any ability: a mode chosen as it triggers is announced (CR 603.3c), its targets are chosen (CR 603.3d), and with no legal choice it is removed. Its target groups are only those of the card its own effects are bound to (and the bare groups belonging to them); no other ability's group of the card, nor the card's first target filter, is its target. A group an effect of it is bound to is its target even when the effect that made it is bound there too. "That player" the resolution was about stands in for a target only as `put` judges an event's object. Targets the maker gave it are kept; a delayed ability its maker made about an object (a `targetId`, targeted or not) acts on that object and chooses nothing (CR 603.7c). The "triggers an additional time" effects don't count an ability a resolution makes (none of them names one, and Roaming Throne's rulings don't settle reflexive abilities); `putMade(gameData, entry, copies)` puts a dungeon room's ability once per venture (CR 309.4c). The choices begin after the resolution, at the door's pumps (`TriggerCollectionService.beginStackDoorChoices`, called by `StackResolutionService` and by `InputCompletionService` once an answer finished a resolution), not while the resolution still has steps to take. A follow-up that is part of the resolution that asked ("if you do", CR 608.2c: a paid cost's effects, an accepted question's payload, the after-cast effect, a library selection's attachment) resolves inline (`EffectResolutionService.resolveNestedInParkedResolution`), never on the stack; only a `QueueReflexiveAbilityEffect` among it makes an ability. "When this creature's echo is paid" is an ability the payment triggers, through `putMade`. The door has no route for an ability with target groups of its own that its card can't declare (Earth Rumble's "up to one target creature you control fights target creature an opponent controls" on a sorcery, whose card groups are its spell's): its handler builds the entry with `madeAbility` first, carries it in its two-step choice made as the ability goes on the stack (CR 603.3d), and hands it, targets chosen, to `putMade`. "Create N tokens. When you do, ..." (`CreateTokenThenEffect`) triggers once for each time the written action occurred (CR 603.12a): once for each written quantity of the written tokens created, rounded down (one doubler: twice; two doublers: four times; a tripler: three times; Ajani, Nacatl Avenger's ruling is the one-token case, and no ruling covers more); tokens a replacement creates instead (Divine Visitation) or adds of another kind (Chatterfang's Squirrels) don't count, and a quantity that isn't fixed triggers it once.

**Engine-made abilities.** An ability the engine makes for a keyword or a rule is a `TriggeredAbility` (a `static final` constant where its effects are fixed) handed to `put` with a record, so the door judges its "if", limit and the "triggers an additional time" effects (CR 603.2d): decayed, melee, battle cry, dethrone, training, double team, granted exalted (the printed exalted route) with `causedBySourceAttacking()` (CR 508.3a); enlist's "when you do" without it (it triggers on the enlist tap, CR 702.154a, so Isshin doesn't double it and Firebender Ascension doesn't count it, as for exert's); flanking; a Siege's defeat; echo, vanishing, suspend's counter removal and cast, egg and refine counters; prowess, increment, a cloaked permanent's ward; undying, persist and madness; and a spell's cascade, storm, demonstrate, replicate, conspire and casualty, whose source is the spell with no source permanent (CR 702.40a, 702.144a). An inherent ability of a rule with no source (the monarch, CR 726.2; the initiative, CR 727.2; rad counters; speed; planeswalking) goes through `putInherent`: controlled by the designation's holder, counted by no doubler, targeting nothing; the initiative's combat-damage ability names the player who takes it non-targeting (`TakeInitiativeEffect(true)`). A spell's, reveal's or rule's "at the beginning of …" (epic, paradigm, rebound, Ertai's Meddling, the opening-hand reveals, Judgment of Alexander, control-loss unattach and tap, regeneration shields, exile returns, Gaze of Pain) is `madeAbility` + `putDelayed`, keeping its source and controller (CR 603.7d, 603.7e). "Combat damage uses the stack" is one `putMade` object. State triggers hand the ability whole to `put` and mark `stateTriggerOnStack` only when it triggered (CR 603.8). The combat damage step's damage abilities stay on the stack through state-based actions, so a named creature that dies is stamped with its last-known information (CR 608.2h), and are moved above the abilities those actions triggered. A triggered mana ability (CR 605.1b) is handed to `putManaAbility` and resolved at once by the collector's resolver (CR 605.4a), never stacked; an ability of a permanent tapped for mana whose record waits for that permanent's mana choice is held (`holdForProducedMana`, `GameData.pendingManaAbilityTriggers`) and, once the choice is made, resolved (a mana ability) or put through `putHeld`. A library search or shuffle is a `LibraryEvent` rules event, emitted by `LibrarySearchTriggerHelper` / `LibraryShuffleHelper` (the shuffle's cause captured as it is emitted) and handed by `RulesEventPipeline` to `TriggerCollectionService.checkLibrarySearchTriggers` / `checkLibraryShuffleTriggers`. A cycling ability that announces its trigger's targets (Rampaging War Mammoth) puts that trigger through `putWithAnnouncedTargets`; any other ability that targets a spell or ability is offered the stack entries its `StackEntryPredicateTargetFilter` admits (`TargetLegalityService.checkSpellTargetOnStack`). A Saga chapter goes through `put` (`SagaChapterService.putChapterAbility`); one that chooses targets (its `TriggeredAbility.chapterTargets()`, its effects, or a random mode's filter) is parked with the chapter's own choice, which finishes it. A permanent's own enters abilities go through `put` as its own zone change; an effect's "if" about a fact fixed as the permanent entered (kicked, evoked, tribute paid) is judged as the ability triggers through `CardEffect.asItTriggersOnEntering(EntryFacts)` (CR 603.4). One selection of permanents and graveyard cards together (`CardEffect.battlefieldAndGraveyardChoice`: Angel of Serenity, Savior of Ollenbock, Aurelia's Vindicator) is the door's mixed route. Turned-face-up and transform abilities go through `permanentChangeRequest` and `put` (Ravager of the Fells declares its two groups with `CONTROLLED_BY_FIRST_TARGET`). "As this Equipment becomes attached to a creature" is the static `AsThisBecomesAttachedEffect`, applied as it becomes attached (CR 614.1c), never a trigger. A group walk constraint relating a later target to the first (`MultiTargetConstraint.MANA_VALUE_AT_MOST_FIRST_TARGET`) offers a first target only if a later group has a legal partner (CR 601.2c).

A handler never builds a reflexive ability's effect with a value bound in, and never picks the value by the effect's class: the entry carries the value in a field it already has and the effect reads it through an amount or predicate. A number paid as the ability resolves ("you may pay {X}. When you do, ... X ...", "pay {2}{R} any number of times ... that many") is the record's X, read with `XValue` and the X predicates (`CardManaValueEqualsXPredicate`); a value the preceding action determined ("that much", "that many", a die roll's result, a revealed or exiled card's mana value, excess damage) is the event value, read with `EventValue` and the event-value predicates (`CardManaValueEqualsEventValuePredicate`, `CardManaValueAtMostEventValuePredicate`, `PermanentManaValueAtMostEventValuePredicate`, which reads `FilterContext.eventValue`: the reflexive target choice and the resolution checks of a triggered ability set it); the power of a creature sacrificed for it is the record's sacrificed power (`SacrificedPermanentPower`); the card discarded for it is the record's discarded-card snapshot (`LastDiscardedCardManaValue`, `LastDiscardedCardTypeCount`, which read the entry's snapshot before the game's last discard, and `StackEntry.carryTriggerRecord` carries it). `QueueReflexiveAbilityEffect` therefore has no "event value as X" option: the reflexive ability has the resolving ability's X and event value, each read as what it is. A player an engine-made ability names ("at the beginning of that player's upkeep", the ability Takklemaggot gains) is part of its trigger (`TriggerOptions.withEventCondition(new TargetPlayerIs(player))`, judged with the player whose upkeep it is), not of a bespoke effect.

Nor does a handler put an effect with a chosen object bound in on the stack, and no follow-up a card writes takes one: a reflexive ability's effect, a library follow-up and a question's payload have no permanent's, card's or player's id filled in for them. (A handler does rebuild its own effect with the progress of its resolution, and hands a step to another handler with what the resolution determined; those are steps of the resolving object, never another stack object.) A permanent an earlier step of the resolution picked (the permanent a library-to-battlefield effect put onto the battlefield, a created token, the targets a "for each of them" step still has to do) is on the resolving entry's picks (`StackEntry.recordPicks`, `ResolutionResults.pickedIds`), and the step that follows reads it there: a `LibrarySelectionFollowUp` is `effect()`, the card's own effect (`MakeChosenPermanentAttackingEffect.pickedPermanent()`, `TransformChosenPermanentEffect.pickedPermanent()`, the `...Selected...` effects), and `LibraryChoiceHandlerService` records the selected permanents on the entry the follow-up resolves in (one is also its chosen permanent). `QueueReflexiveAbilityEffect.aboutPickedPermanent(effect)` takes the next pick as the reflexive ability's source permanent, so one such step per created token puts one ability on the stack for each. What the preceding action determined about a reflexive ability ("that player" chosen at random, "the tapped creature") is set on its record, as its triggering player and permanent, through `QueueReflexiveAbilityEffectHandler.resolve(gameData, entry, queueEffect, recordSetup)`; the reflexive target choice's `FilterContext` has the record's triggering permanent and player, so the effect's target is written with `PermanentControlledByTriggeringPlayerPredicate` and `PermanentPowerAtMostTriggeringPermanentPowerPredicate` and judged again as the ability resolves. A question the resolving ability asks about a card names the card (`PendingMayAbility.targetCardId`; `BecomeCopyOfCardUntilEndOfTurnEffect.ofQuestionCard()`). `scripts/step15-run17z16c3c-scan.py` lists every effect a service constructs with runtime data and where it goes; a construction it cannot classify prints `UNCLASSIFIED`.

A spell-cast trigger's "that spell" — the spell to copy, counter or exile, "its controller", "its colors", "its mana value" — is the stack entry's triggering spell (`StackEntry.setTriggeringSpell`, a copy of the spell's stack entry as the ability triggered), set by the collector that puts the ability on the stack (the generic cast collector's non-targeted entries, the delayed cast trigger, the demonstrate self-cast trigger), never bound into the effect: effects read the live spell while it is on the stack and `getTriggeringSpellSnapshot()` once it has left (CR 608.2h), and `TargetSpellManaValue` falls back to it. "That spell's mana value" is `TargetSpellManaValue` (the live spell, else that snapshot), never `EventValue`: the generic cast collector records the cast event's value on every entry and choice whatever the effects are (the kick count of a kicked-spell trigger, else the spell's mana value as the ability triggered), only a fallback where no snapshot is kept, and judges no effect by its class for it; the handlers that read the spell's mana value (cascade, Kellan, Living Breakthrough, Lady Loki, Ancient Cellarspawn, The Ruinous Powers, Baral and Kari Zev) evaluate `TargetSpellManaValue` too. A "you may" carries it through `PendingMayAbility.withTriggeringSpell` into the entry the accepted ability resolves as, and `RemoveCounterFromSourceThenEffect`'s reflexive entry copies it. The copy-for-each effects of a cast trigger (Mirrorwing Dragon, Precursor Golem, Hive Mind, Glimmervoid Basin and the like) read it through `CopySupport.triggeringSpell`, their "targets only …" conditions the trigger's stack-entry filters. A graveyard target restricted by the spell's name (`CardSharesNameWithTriggeringSpellPredicate`, Harness the Storm) is chosen against the spell `SpellGraveyardTargetTrigger.triggeringSpell` carries, which the graveyard target operation keeps for the entry and its check as it resolves; an intervening "if" on the spell (`TriggeringSpellMatches` as `TriggerOptions.withInterveningIf`, Spellweaver Helix) is judged on it as it is cast and again as the ability resolves. "Whenever a spell you control causes you to gain card advantage" (Toofer, Keeper of the Full Grip) is an event of the spell's resolution: the spell records every player's card count on its entry as it begins to resolve (`StackEntry.cardCountsBeforeResolution`), and `StackResolutionService` judges it as the spell finishes resolving and collects the abilities with the spell as their triggering spell. A graveyard target restricted by the spell's mana value is chosen as the ability goes on the stack with that mana value as the choice's X (`SpellGraveyardTargetTrigger.xValue`, which `ReturnCardFromGraveyardEffect.requiresManaValueEqualsX` / `AtMostX` and the X card predicates read). "Copy that spell or ability" (Bill Potts) is `CopyTriggeringSpellOrAbilityEffect` on one ability of a cast and an activation condition, and so is every activation trigger's "copy that ability" (Rings of Brighthearth, Illusionist's Bracers), behind the "you may" the card prints. Every "whenever [a player] activates an ability" ability triggers on the `SpellEvent.Activated` that `TriggerCollectionService.collectActivationTriggers(gameData, Activation)` emits once per activation when the activated ability is on the stack and its costs are paid (CR 602.2b, CR 601.2i; a mana ability's entries wait in `pendingManaAbilityTriggers`), whatever the ability's effects are: `SpellTriggers` matches the trigger's event (any ability, not a mana ability, exhaust, embalm or eternalize) and player, judges `AbilityTrigger.kind`, `source` (against the activated permanent as it last existed; an ability of a card in a hand, graveyard, exile or the command zone has none, CR 109.2; an Aura or Equipment whose permanent left paying the costs is attached to nothing), `withStackEntryFilter` and `withPayment`, the limit and the conditions, and the event condition, and hands the ability to the stack door (which judges the limit and the intervening "if", "if mana from a Treasure was spent to activate it" a fact of the activation the context carries) with its record (`activationRecord`): that ability's stack entry as its triggering spell, the `ActivatedAbility` as `triggeringActivatedAbility`, the activated permanent and its controller as the triggering permanent, the life paid to activate it as its event value and the activating player as "that player" of an "an opponent activates" trigger. Its targets are chosen as it goes on the stack. No call site collects a subset, and nothing is collected before the costs are paid; discarding Circling Vultures is a special action (CR 116.2e) and collects nothing. An "if" of the effect on that spell ("copy that spell if it targets a permanent or player", `TriggeringSpellMatches`) is judged as the ability resolves by `EffectResolutionService` against the same spell; "that creature" / "those permanents" the spell targets (`PermanentIsTargetOfTriggeringSpellPredicate`, Loki, God of Lies, Dack Fayden's emblem) and Vesuvan Duplimancy's "that artifact or creature" are its targets as the ability triggered, a later change of target not moving them. A "that many" count of the spell's targets (`TriggeringSpellTargetCount`) is counted as the ability resolves, from the live spell or that snapshot. Every cast trigger's record takes the snapshot from the stack as it triggers, the door's parked record carrying it to the entry its choice makes. "Copy that spell" is `CopyTriggeringSpellEffect`, whose modifiers (`permanentSpellCopiesAreTokens()`, `withGrantedKeywords`, `withoutSupertypes`, `asAdditionally`, `withCopies`, …) the shared `CopyControllerCastSpellEffectHandler` machinery applies. A permanent target restricted by "that spell's mana value" (`PermanentManaValueEqualsXPredicate` or `PermanentMaxManaValueXPredicate` in the ability's target filter: Skyfire Kirin, Hammerhead Tyrant's "up to one" target) is chosen against the spell's mana value as the ability's X, which `TriggeredAbilityQueueService` (or the multi-target choice) puts in the target choice's filter context and the resolution check reads from the entry. "The amount of mana spent to cast that spell" (`ManaSpentToCast`) and "if at least N mana (from creatures) was spent to cast it" (`SpellManaSpentAtLeast`, `SpellCreatureManaSpentAtLeast`, `SpellManaSpentGreaterThanSourcePower`) read what the spell recorded as it became cast (`StackEntry.manaSpentToCast` / `creatureManaSpentToCast`, set as `TriggerCollectionService.checkSpellCastTriggers` begins; 0 for a copy that wasn't cast, CR 707.10), from the entry's snapshot of the spell as the ability resolves and from `ConditionContext.triggeringSpell` (the entry's, else the spell on the stack as it triggers): every cast-trigger entry records its triggering spell, the single- and multi-target choices and the graveyard and hand readers included. A cast trigger's X is the spell's. An effect's own filter "with that spell's mana value" (`DestroyAllPermanentsEffect` with `PermanentManaValueEqualsTriggeringSpellPredicate`, `RevealHandAndDiscardMatchingCardsEffect` with `CardManaValueEqualsTriggeringSpellPredicate`: the Kirins) is bound by its handler to the entry's triggering spell as the ability resolves (`AmountEvaluationService.bindTriggeringSpellManaValue`: the live spell, else the entry's snapshot, with its chosen X); only the target restrictions by it keep the spell's mana value as the ability's or the choice's X. "For each color of mana spent to cast that spell" (`ColorsSpentToCast`) reads the colors the spell recorded as it was cast (`StackEntry.colorsSpentToCast`) as the ability resolves, from the spell on the stack, else from the entry's snapshot of it (CR 608.2h). "That player" of a cast trigger is the caster, the non-targeting entry's `targetId` the `TRIGGERING_PLAYER` recipients read, and "the same name as that spell" is `CardSharesNameWithTriggeringSpellPredicate`, which the `CardsInGraveyard` count reads from the entry's triggering spell. "Counter that spell" is `CounterSpellEffect` (or `CounterUnlessPaysEffect`) on a filtered cast trigger, which the stack door aims at the triggering spell on a non-targeting entry (Chalice of the Void's and Void Mirror's conditions stack-entry filters, Cephalid Shrine's count read as it resolves); an effect that exiles "it" or has "that player" choose (Knowledge Pool, Possibility Storm, Eye of the Storm, Ice Cave's payment) reads the spell, the caster and the source permanent from the entry as it resolves. "Copy it for each other instant and sorcery spell you've cast before it this turn" (Thousand-Year Storm) is `CopyTriggeringSpellEffect().withCopies(new SpellsCastBeforeTriggeringSpellThisTurn(filter))`, counted as it resolves up to the triggering spell's place among its caster's spells this turn, which the cast collector keeps on the entry (`StackEntry.triggeringSpellCastIndex`). Storm (`CopyTriggeringSpellEffect.storm()`, CR 702.40a) counts every player's spells before the triggering spell the same way, up to its place in the turn's cast order (`StackEntry.triggeringSpellTurnCastIndex`); the self-cast collector records the triggering spell, both places and its X and repeatable additional cost payments on every "copy this spell" entry, so replicate's, gravestorm's and the other counted copies' amounts read them as the ability resolves. A cast trigger's record names the caster as its triggering player, which its parked target choice carries, so "another target player" (`PlayerOtherThanTriggeringPlayerPredicate`, The Lord of Pain) is judged against the caster as the target is chosen and against the entry's triggering player as it resolves. A spell's own "whenever this spell is countered or fizzles" ability (Trial and Error) has the spell as it last existed on the stack as its triggering spell. A spell-copy trigger's "that spell" is the copy the event was about: the copy collector's record names it as the entry's triggering spell, the copying player as "that player" and the copy's mana value as the event's value (Parnesse, the Subtle Brush's `CopyCopiedSpellForTargetPlayerEffect`).

A becomes-the-target trigger's "that spell or ability" and "its controller" are the stack entry's triggering spell, never chosen by the effect's class: every becomes-the-target ability triggers on a `TargetEvent` (`BECAME_TARGET_OF_SPELL`, `BECAME_TARGET_OF_ABILITY`, `TARGETS_CHOSEN`, emitted by `TriggerCollectionService.checkBecomesTargetOf{Spell,Ability}Triggers` and `checkTargetChoiceTriggers`) and goes to the stack door through `TargetTriggers.putTargetAbility`, whose record (`recordTargetingObject`) names the spell or ability that targeted as the entry's triggering spell (a copy as it was then, read live while it is on the stack and as it last existed there once it has left, CR 608.2h, through `CopySupport.triggeringSpell`) and its controller as the triggering player, whatever the effects are, with what the collector's event names besides ("that creature" as a non-targeting `targetId` or the triggering permanent, "that player"). The door aims an effect that acts only on a spell or ability ("counter that spell or ability unless its controller pays", ward) at that object on the stack without targeting it when the record names no object but a player; ward is identified by that rule, not by a counter class. The door counts "if a creature you control becoming the target … causes a triggered ability of a permanent you control to trigger, it triggers an additional time" (Valiant Emberkin) from the request's event (`TriggerContext.BecomesTarget`) beside every other doubler. Pawpatch Recruit's "other than that creature" and Scalelord Reckoner's "that player controls" are their target filters (`PermanentIsTriggeringPermanentPredicate`, `PermanentControlledByTriggeringPlayerPredicate`). "For the first time each turn" is the trigger's `TriggerLimit.FIRST_TIME_EACH_TURN` (Glyph Keeper). A delayed triggered ability an activation creates is the activator's (CR 603.7e) and independent of its source's abilities: Giant Oyster's activation queues a `DelayedDrawStepTriggerWhileSourceTapped` (read by `StepTriggerService` at each of that player's draw steps, ended when the source untaps or leaves) and a `DelayedSourceUntapsOrLeavesTrigger` (put on the stack by `UntapLockReleaseService`).

A triggered ability's "its counters", "that creature's name", "its mana value", "that artifact", "the Auras attached to it" — the last-known information of the permanent a death, departure or sacrifice was about — is the stack entry's triggering permanent (`StackEntry.setTriggeringPermanent(lastKnown, attachments)`, a copy of the event's battlefield snapshot, CR 603.10a), set by the collector that puts the ability on the stack, never bound into the effect: effects read `getTriggeringPermanentSnapshot()`, `getTriggeringAttachments()`, `triggeringPermanentCounters()` / `triggeringPermanentCounterCount(type)` as they resolve, and an amount reads it through `CountersOnTriggeringPermanent`; a predicate that compares with "it" or its controller reads `FilterContext.triggeringPermanentId` while that permanent is on the battlefield and `FilterContext.triggeringPermanentSnapshot` once it has left (`PermanentSharesCardTypeWithTriggeringPermanentPredicate`, `PermanentControlledByTriggeringPermanentControllerPredicate`; the snapshot is set by `SacrificePermanentsEffectHandler`, the id by `TriggerTargetCollector` and the resolution recheck in `TargetLegalityService`), never a source snapshot rebound to the triggering permanent. A trigger whose targets are chosen as it goes on the stack carries it through `DeathTriggerTarget.withTriggeringPermanent`, `SelfTriggeredAbilityTarget.withTriggeringPermanent`, `EntersTriggerTarget.withTriggeringPermanent` or `SpellTargetTriggerAnyTarget.withDepartedPermanent`. Every field that records the trigger event (the triggering permanent, card, cards, spell, player, the event value and payloads) is copied by `StackEntry.copyTriggerEventFrom`, which the copy constructor (and so the simulation copy) and `CopySupport.createCopyStackEntry` for a copied activated or triggered ability both call, so a copy of an ability reads the same trigger event (CR 707.10); a new trigger-event field goes there, not into the copy constructor alone. A damage trigger's "that source" is the triggering permanent too (`setTriggeringPermanentId`, with `setTriggeringPermanentControllerId` for the source's controller as it dealt the damage; a spell source has only the controller) and the damage its event value: "that source's controller" is `GameQueryService.findTriggeringPermanentController` — the current controller while the source is on the battlefield, otherwise the last known one (CR 608.2h) — which the `TRIGGERING_PERMANENT_CONTROLLER` recipients read. The group an event is about — "them", "each of them", "one of them" — is the entry's triggering permanents (`setTriggeringPermanentIds`): the matching dealers of a `TriggerOptions.ONE_OR_MORE` combat damage batch, and the matching attackers of a filtered `Triggers.youAttack()`, whose entry also has them as its attacking snapshots (`TotalPowerOfControlledCreatures.declaredAttackers`, `BoostAllOwnCreaturesEffect.forDeclaredAttackers`) and as its declared `GrantScope.TARGETS` recipients; `EachPermanentScope.TRIGGERING_PERMANENTS` reads them. The tapped permanent of a tap trigger (with its last-known snapshot, Haunted One), the permanent an attachment's becomes-the-target ability watched (Fractured Loyalty) and the attacker of an "attacks you" trigger (whose `withFilter` the collector judges as the creature is declared an attacker) are the triggering permanent too; the card of a graveyard event is the entry's triggering card with its graveyard incarnation (`setTriggeringCard`), or for a batch its event cards with theirs — never an id bound into the effect.

Simultaneous death batches snapshot continuously granted abilities that trigger on a zone change, the permanent's own (`Triggers.dies(THIS)` and the like) or another's ("whenever a creature dies"), before moving any permanent. The snapshot preserves abilities supplied by a paired creature or another permanent dying in the same event and is cleared when that event ends.

`SourceCardInGraveyard` ("if this card is in your graveyard") reads the graveyard incarnation the stack entry keeps for its source card (`StackEntry.sourceCardGraveyardEntryVersion()`: the one the collector records with `setSourceGraveyardEntryVersion`, carried by a target choice such as `AttackTriggerTarget.withSourceGraveyardEntryVersion`, else the triggering card's when the source is the triggering card, as for "when this dies"), so leaving and reentering the graveyard cannot satisfy an older Bridge from Below ability (CR 400.7). No collector binds the version into the condition. The source card's stay and the triggering card's are two records: every "this card" effect (`ReturnSourceCard…`, `ExileSourceCard…`, `ShuffleSelfFromGraveyardIntoLibrary`, a `CardIsSelfPredicate` return, persist, `ForcedCostOrElseEffect`'s source check, …) reads `sourceCardGraveyardEntryVersion()`, and `getTriggeringCardGraveyardEntryVersion()` is only the stay of the card the event was about (the discarded, milled or dying card). Every collector of an ability of a card in a graveyard records its stay with `setSourceGraveyardEntryVersion` whatever the effects are, the may path carries it (`PendingMayAbility.sourceGraveyardEntryVersion`), and a graveyard target choice records a source card still in a graveyard as the ability goes on the stack. The discard collectors record the discard on every entry (`DiscardRecords.record`: the discarding player as triggering player and non-targeting target, the discarded cards as triggering cards with their stays in `eventCardGraveyardEntryVersions`, a lone card also as the triggering card, and a discard event's count as the event value), as the cards-put-into-a-graveyard collectors record their cards (`MiscTriggerCollectorService.recordCardsPutIntoGraveyard`). "Whenever a player cycles a card" has the same default (cycling discards the card, CR 702.29a), and a targeted discard or cycling ability's `DiscardControllerTriggerTarget` carries the record (`withDiscard`) into the entry it makes. The scry and surveil defaults record the player as triggering player (and an opponent's as non-targeting "that player"). The tap-for-mana abilities have one default (`TapTriggers`): the entry records the tapping player (triggering player), the tapped permanent (triggering permanent with its last-known snapshot), the produced mana colors and the source snapshot whatever the effects are; a triggered mana ability (`TapTriggers.isTriggeredManaEffect`, CR 605.1b) resolves at once through its effects' handlers (CR 605.4a), parked while the permanent's own mana choice is open when an effect `readsProducedMana()`; a targeted one goes to `SpellTargetTriggerAnyTarget` with the same record. Who taps and which permanent is the trigger (`youTapLandForMana()`, `enchantedLandTappedForMana()`, `youTapThisLandForMana()`, `opponentTapsPermanentForMana()`: `TapTrigger.judgedTapRelation()`), judged by the caller; "its controller adds" is the tapped permanent's controller (`TappedLandManaSupport.tappedPermanentController`), not the tapping player (Piracy).

Delayed graveyard returns use stack entries and `CardIdSetPredicate` with graveyard entry versions.

A graveyard target restricted by the trigger event is chosen as the ability goes on the stack, before its entry exists, so the restriction is read from the trigger record (the entry the collector built for the ability that chooses nothing, `GameData.queuedTriggerRecord(choice)`), never from an X of the choice and never in a rebuilt effect: `processNextSpellGraveyardTargetTrigger` evaluates the effect's mana value limit (`dynamicMaxManaValue(new EventValue())`, `TriggeringCardManaValue`) with the record as the amount's stack entry and gives the filter the record's event value (`CardManaValueEqualsEventValuePredicate`), and as the ability resolves the same amounts and predicate read the stack entry (`TargetValidationContext.eventValue`). A collector therefore gives a target or graveyard choice the X its record has, not the damage dealt or a mana value: an effect's "that much" is `EventValue`. A death trigger's collector evaluates the effect's `dynamicMaxManaValue` as the ability triggers (the dying object as it last existed as the amount's source) into `DeathTriggerTarget.graveyardTargetMaxManaValue`, which the entry keeps as `StackEntry.graveyardTargetMaxManaValue`.

A triggered ability's "if that land is a Forest" / "that creature's creature types" reads the triggering permanent as it is when the ability resolves, never a value bound as it triggered: once the permanent has left the battlefield, `PermanentRemovalService` has recorded its last-known characteristics on every stack entry it triggered (`StackEntry.triggeringPermanentLastKnownCard`, the layered types, subtypes and colors, CR 608.2h), which `EffectResolutionService` gives a `TriggeringPermanentHasSubtype` "if" or "instead" as its triggering card. Evolve's comparison is the intervening "if" `TriggeringPermanentHasGreaterPowerOrToughnessThanSource`, judged as the ability triggers and again as it resolves (departure snapshots for a creature that left). "That creature's power / toughness" is the amount `TriggeringPermanentPower` / `TriggeringPermanentToughness`: the triggering permanent's current value while it is on the battlefield, else the value the collector recorded as the ability triggered (a dying creature's last-known one), else its departure snapshot; an enter collector records the entering creature on the entry, never in a rebuilt effect (Archon of Redemption, Hamletback Goliath, Cream of the Crop). Likewise an enter trigger's "put counters on it", "it gets +X/+Y", "transform it", "attach this to it" and "become a copy of that creature" are effects the card writes reading the entry's triggering permanent (`PutCounterOnTargetPermanentEffect.onTriggeringPermanent`, `PermanentReference.TRIGGERING`, `GrantScope.TRIGGERING_PERMANENT`, the `ofTriggeringPermanent()` forms); the enter collector puts them on the stack as written. No effect asks the enter collector to bind the entering permanent as its target or source any more: graft, Agent's Toolkit, soulbond's other half, "it connives", "deals N damage to it" (`DealDamageToTriggeringPermanentEffect`), endure, the power branches, Madame Null, Mana Echoes, Eldrazi Mimic and the graveyard Auras and Equipment that return attached to "that creature" read the entry's triggering permanent as they resolve, and a "you may" goes on the stack and asks as it resolves (CR 603.5).

Divided damage assignments belong to the individual stack entry; copies retain their division
while offering legal replacement targets. Additional ETB abilities on token copies are abilities
of their own, so they keep their targets and resolution separate from the copied abilities (CR 603.3).

`CharacteristicState.meleeInstances` preserves multiple melee abilities. Each instance triggers
separately and counts players attacked by declared attackers, excluding planeswalkers and battles.

"You may exert this creature as it attacks" is a static ability, an optional cost to attack (CR 701.43d, 508.1g): `ExertAsItAttacksEffect` (with an optional condition, Combat Celebrant). The attack collector asks it as the creature attacks, off the stack, and accepting exerts the creature at once (`SkipNextUntapEffect.exert()`). The exertion fires "whenever you exert a creature" (`TriggerCollectionService.checkExertTriggers`) and the linked "when you do" (`Triggers.exertedAsItAttacks()`, `ActionWatch.ON_EXERTED_AS_IT_ATTACKS`, CR 607.2h), a printed triggered ability of the creature that goes through `put`. A modal reflexive ability's modes are announced at the door like any other's.

Separate next-spell-copy effects each create their own triggered stack entry.

Simultaneous spell-cast triggers retain their triggering spell identity. Trigger ordering (CR 603.3b) is one interaction for every batch: once no trigger is waiting for targets or a may choice, `TriggeredAbilityQueueService.beginTriggerOrder` (called from `AutoPassService` before priority and before each combat-trigger auto-resolution) asks each player in APNAP order whose unordered triggers include two or more non-equivalent ones to place them from the bottom upward via `ChoiceContext.TriggerOrder`. Entries are reordered only within the positions that player's batch already occupies. `StackEntry.triggerOrderChosen` marks every trigger that has been through ordering (and everything on the stack when the top resolves) so it never joins a later batch; it survives simulation copies. Players in `GameData.playersAutoOrderingTriggers` keep the order the triggers were collected in without a prompt — the test harness enables this for both players by default (`harness.setAutoOrderTriggers(player, false)` to test ordering).

Divided-damage, divided-prevention and divided-counter triggers (`DealDividedDamageEffect` with `etbAssignments` and no target restriction, `PreventDividedDamageEffect` with `etbAssignments`, `DistributeCountersAmongTargetsEffect` in `CHOSEN` mode with `etbAssignments` and no target restriction, e.g. Glint Weaver, and the death triggers' `DistributeCountersAmongCreaturesOnDeathEffect`, also inside a `MayEffect`, e.g. Jugan) that reach the stack without a division announce it before priority: `AutoPassService` calls `StackedDividedDamageTriggerService.announceNextDivision` right after `StackedModalTriggerService.announceNextMode`. The amount is evaluated against the stack entry, so a death trigger's total reads the dying creature (`CountersOnTriggeringPermanent`, `TriggeringPermanentPower`). Kuldotha Flamefiend's `SacrificeArtifactThenDealDividedDamageEffect` (also inside a `MayEffect`) announces its zero or more targets the same way (`StackedDividedDamageTargets.allowsNoTargets`; zero targets is `StackEntry.divisionAnnounced` with an empty division). Nothing staged before the ability triggered is taken over; a divided enter ability with a declared target group (Fury, Bogardan Hellkite, Verdurous Gearhulk) chooses its targets through that group and divides among them in `ETBTokenTargetService`. The targets and division are chosen by the ability's controller, or for Grand Ossuary by the dying creature's controller; otherwise the controller picks one to `maxTargets` targets (`MultiPermanentChoiceContext.StackedDividedDamageTargets`) and divides through `ChoiceContext.CounterDistributionAssignment` with `stackEntryId` set, which records the division on the existing entry via `StackEntry.announceDamageAssignments`. An entry with no legal target is removed (CR 603.3d).

Delayed damage triggers retain the watched permanent as their damage source. `StackEntry.damageSourceControllerId` preserves that source's controller independently from the delayed ability's controller when the source leaves the battlefield.

A delayed triggered ability belongs to the resolution that created it (CR 603.7a): `StackResolutionService.resolveTopOfStack` counts the stack objects that begin to resolve (`GameData.resolutionOrdinal`, copied for simulations and kept across a turn restart) and `GameData.queueDelayedAction` stamps each `DelayedAction` with it (`DelayedAction.scheduledBy`; `DelayedPermanentAction`, `ExilePermanentAtNextUpkeep` and `ExileToOwnerGraveyardAtNextUpkeep` keep it as `schedulingResolution`). A queue that puts several actions on the stack as one ability groups by the source card, the controller and that resolution (`PermanentRemovalService.processDelayedPermanentActions`, `StepTriggerService.queueDelayedPermanentExiles`, the two upkeep queues), so one resolution's "exile them at the beginning of the next end step" is one stack object and two resolutions of one source are two. The counted "when you next cast / activate ..., copy it" abilities are an entry per unit. A "when [source] leaves the battlefield or becomes untapped" ability is a `DelayedSourceUntapsOrLeavesTrigger` per resolution (Giant Oyster; Tawnos's Coffin, whose effect is `ResolvePendingExileReturnEffect`). `scripts/step15-run17z17d-scan.py` lists every delayed queue and how it groups.

`DelayedZoneChangeTrigger` registers a one-shot watch on a permanent's identity and maps its departure destination to an existing effect. It is independent of that permanent's abilities, so Earthbend returns survive ability removal. Every departure consumes the watch, including destinations without an effect. The triggered entry stores the departed card's identity; graveyard entry versions bind after the card reaches the graveyard and prevent an old trigger from returning a later incarnation.

Controller end-step abilities with explicitly bound target groups use the existing mixed-target trigger continuation for permanent, player, and graveyard groups. Graveyard candidates pass both the group's card predicate and the bound effects' shared target validators before being offered. Life gained or lost restrictions use the triggered ability's controller even if its source changes control or leaves before resolution.

Generic triggered-ability doublers include their last-known simultaneous death snapshots when
collecting abilities caused by those deaths.

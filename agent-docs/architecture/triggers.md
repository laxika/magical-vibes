# Triggers

Triggered abilities: rules events, the trigger pipeline, the collectors, and what a stack entry records about its trigger event. Never read whole: grep for the class or wording you are changing and read that paragraph.

- **Rules events and the trigger pipeline**: `GameData.rulesEvents` (`model/rules/RulesEventLog`) records synchronous `RulesEvent`s inside the action, grouped into one `RulesEventBatch` per occurrence (CR 603.2c); unlike domain events, rules code reads them. Zone changes (`ZoneChangeEvent`: card, from, to, cause, last-known permanent, controller) are emitted at three kinds of choke point: `PermanentRemovalService.processRemovalCleanup` for every battlefield departure (snapshot from `DepartureService`'s batch snapshot when there is one, CR 603.10a), `BattlefieldPlacementService.completePlacement` for every entry, and GameData's own hand, library, graveyard, exile, command-zone and stack lists for every other arrival, so a card added straight to one of those lists is still a zone change. The log remembers each card's last zone, so an arrival names where the card came from; a move inside one zone emits nothing, and a departure that a replacement sends elsewhere (CR 614.6) is rewritten rather than doubled. Engine code that moves a card for a reason names it around the move (`setCause`/`restoreCause`: destroy, sacrifice, discard, mill), and code that moves several cards at once opens a scope (`beginBatch`/`endBatch`; the permanent-leave, graveyard-leave and card-exile batch scopes and mill already do). Anything that refills zone lists without moving cards (simulation copies, the turn-restart restore) must run between `suppress()` and `resume()`. Every leave path in `PermanentRemovalService`, GraveyardService's `addCardToGraveyard`, mill and the Aura sweeps open a scope, so a departure's batch closes only after its card arrived (and was redirected). Each batch goes, as it closes, to the trigger pipeline (`service/trigger/pipeline`: `RulesEventPipeline` → `TriggerIndex` candidates → `TriggerMatcher` → `TriggeredAbilityStackService`), registered on every game by `GameSetupService` and carried into simulation copies; `beginTriggerOrder` only drains closed batches afterwards. The pipeline puts abilities with a real `Trigger` (`ZoneChangeTrigger` via `Triggers`, added by `Card.addTrigger` or `SpellTarget.addTrigger`, granted as `new TriggeredAbility(trigger, effect)`) on the stack with their `TriggerOptions` (intervening "if", limits, multiplicity, and the event condition: a condition the trigger event itself requires, checked as the ability triggers and not again on resolution, CR 603.2) and additional-trigger copies. No triggered ability has a legacy view any more (step 14, run 16q): every collector reads the abilities, their filters and options. Every zone change but "when this enters" and every permanent change is read as an ability by the pipeline, which judges its filter and options, and by the readers outside it (face-up planes, schemes, the abilities a resolved spell registered) through `ZoneChangeAbilityReader`, which takes an ability without options and throws on any other. The ability rejects "once each turn for each creature" and a trigger mode as it is built. A permanent phasing, transforming or being turned face up is a `PermanentChangeEvent` (not a zone change, CR 702.26d), matched the same way against `PermanentChangeTrigger`s (`Triggers.phasesOut`, `phasesIn`, `transforms`, `transformsToBackFace`, `transformsToFrontFace`, `turnedFaceUp`); a phasing-out permanent's own abilities look back to it as it was (CR 603.10b). "As this is turned face up" and "as this transforms into" are static abilities, applied at the choke point. Every "when this dies / leaves the battlefield / is put into a graveyard from … / is milled / when you sacrifice this" ability is one now (the old `ON_DEATH`, `ON_SELF_LEAVES_BATTLEFIELD` and `ON_SELF_PUT_INTO_GRAVEYARD_FROM_*` slots are gone), and so is every "whenever [a creature, another creature you control, a nontoken creature, equipped creature, the creature it haunts, …] dies" ability (the old `ON_*_CREATURE_DIES` slots are gone). A trigger's `ObjectRelation` and filter say which moving object it watches and whether that can be the source itself ("a creature you control" includes it, "another" doesn't, "this or another" always does). `TriggerIndex.observerCandidates` lists the other objects that see a permanent die, as they were just before the event (CR 603.10a): the battlefield, the permanents that left in the same batch (their departure events), graveyard cards that were there before it and the exiled cards that haunted it; the filter is judged on the departed copy's last-known card. Their abilities go on the stack through `TriggeredAbilityStackService.triggerOnce`, which hands them to `TriggerCollectionService.triggerCreatureDeath`/`triggerCreatureDeaths`: the old per-slot collectors' bodies, picked by `CreatureDeathWatch`, with their handlers in `DeathTriggerCollectorService.dispatchCreatureDeath` (until step 15). "One or more" deaths is `TriggerMultiplicity.ONE_OR_MORE`. Death triggers a resolved spell registered, emblems', the delayed watchers and planes' are still collected at the choke point (`checkCreatureDeathRegisteredTriggers`). The source's own zone-change abilities carry no trigger-only wrapper: a condition on the object as it last existed is the `THIS` trigger's filter (`TriggerMatcher` judges it on the last-known copy), any other intervening "if" and the limit are `TriggerOptions`. Nor do other objects' zone-change and permanent-change abilities, but for "another object enters" (step 12a's `ZoneChangeWatch` family): a restriction on the moved object is the trigger's filter and "you control" its relation, and `ZoneChangeWatch.of` finds the watch of a trigger narrowed that way (filter `AllOf(X, …)` → the watch of filter `X`, any other filter → the watch of no filter, unless `CreatureDeathWatch.collects` claims a dies trigger; `onlyDuringYourTurn()` → the watch without it; `whileCasting(CardPredicate)`, "while casting a spell with emerge", is judged by `TriggerMatcher` on `ZoneChangeEvent.castingSpell`, the spell `RulesEventLog.setCastingSpell` names while its costs, or a mana ability activated with a cast `ManaPaymentIntent`, are paid). The watch bodies take the "do this only once each turn" limit from the ability (`TriggerMatchContext.markSourceOncePerTurnOnAcceptance`), and "this or another [restricted] one" is one ability with a `THIS` condition, collected by the source's own path, and an `ANOTHER_…` condition, collected by its watch. The source's own zone-change ability ("when this dies", "leaves the battlefield", "is put into a graveyard from anywhere", "when you sacrifice this") goes on the stack through the stack door (`TriggeredAbilityStackService.trigger` hands it to `put`) with one record whatever its effects are (`ownZoneChangeRecord`): the source as it last existed (snapshot, triggering permanent with its attachments, last-known power as the event value, mana value, how it was cast), the card with its new zone's incarnation (CR 400.7) and the card its linked ability exiled (CR 607.2a); the door announces its mode and chooses its targets like any ability's, a graveyard target an own departure's effect describes itself ("return any number of target Spirit cards", Iname, Life Aspect) included, judges "another target card" against the source's physical card (a copy's, Gixian Puppeteer) and evaluates a graveyard target's mana value limit with the departed permanent as it last existed (Soulshift, CR 603.10a). "A creature dying causes an ability to trigger an additional time" (Teysa Karlov) is the request's `withCreatureDying()`, which an ability that triggers on a sacrifice doesn't set (her ruling). Another object's zone change, phasing, transforming or being turned face up goes through `triggerOnce` / `triggerPermanentChange`: the collector (`TriggerCollectionService.zoneChangeRequest` / `permanentChangeRequest`) judges what the watch adds (the watcher's own move, the commander, "for the first time each turn", Torpor Orb's kind) and records the event (`zoneChangeRecord`: a departure as above, an entry with the entering permanent's controller, power, toughness and the player it attacks, a card's move with its stay, "one or more" as the batch's objects and count or total power, "that player" as the non-targeting target and triggering player), and the door puts it; an entering doubler (Panharmonicon) reads the request's `TriggerContext.PermanentEnters` event. Every zone-change watch and every creature-death watch (`CreatureDeathWatch`) goes through the door (`TriggerCollectionService.zoneChangeRequest`, whose `zoneChangeRecord` records the death or departure whatever the effects are); only the watches `keepsLegacyPermanentChangeRoute` lists (face-up and transform) still go to their old putters. A "whenever one or more tokens enter" ability triggers once for the batch and a "whenever a token enters" one once for each token: the card writes which (CR 603.2c), and no effect's resolution condition splits a batch. A permanent that left the battlefield is the record's triggering permanent with its owner, and its card's exile stay only when the card is in exile. The door chooses a graveyard target the effect describes itself (`GraveyardTargetingSupport.findTarget`: Iname, Exhumer Thrull's haunted creature) for any departure event, its mana value limit judged with the departed permanent as source and the record as the entry (`AmountEvaluationService.evaluateAtDeath`, so `TriggeringPermanentManaValue` reads the last-known object, CR 603.10a). "Other than it" of a graveyard target is `CardIsTriggeringCardPredicate`, bound to the record's triggering card as the target is chosen (`AmountEvaluationService.bindTriggeringCard`); `CardIsSelfPredicate` is the source's card. A door choice pump (`processNextAttackTriggerTarget`, `processNextETBTokenMultiTargetTrigger`, `processNextSpellGraveyardTargetTrigger`, `processNextTriggeredModalTrigger`) begins nothing while a choice awaits input, so a second caller can't write over the prompt and lose a parked ability. A departure event carries what look-back abilities read just before the permanent left (CR 603.10a): its last-known permanent (with the permanents that damaged it this turn), the zone-change abilities other permanents granted it, its attachments, the exiled cards that haunted it, Hushbringer's suppression and the spell whose cost it paid. "At the beginning of [player's] [step or phase]" abilities have a real `StepTrigger` too (`Triggers.upkeep`, `drawStep`, `precombatMainPhase`, `beginningOfCombat`, `endOfCombat`, `postcombatMainPhase`, `secondMainPhase`, `endStep`, with an `ActivePlayer`: `YOU`, `ANY`, `OPPONENT`, `ENCHANTED_PLAYER`, `ENCHANTED_PERMANENT_CONTROLLER`; CR 603.2b). A step beginning is no rules event: `StepTriggerService` still collects them where the old step slots were collected, with each step's old grouping and target routing. A step ability has no legacy view: every reader reads the abilities by trigger and zone (`Card.getTriggeredAbilities(trigger, zone)`, `GameQueryService.getEffectiveGraveyardTriggeredAbilities`, `GameData.perpetualAbilities`, `Permanent.getTemporaryTriggeredAbilities` / `getPersistentTriggeredAbilities`, `GrantedTriggeredAbilitySupport.grantedTriggeredAbilities`, `GrantedUpkeepEffectSupport`) and hands them to `StepAbilityReader`, which checks the event condition and the intervening "if" as the ability triggers, in the condition context the step's body gives (its source, its controller and, for "that player", the player whose step it is), judges and marks "this ability triggers only once" by `TriggeredAbility.limitKey()`, throws on any other limit or a multiplicity, and returns the effects with the intervening "if" wrapped around each as the `ConditionalEffect` that checks it again as it resolves; the body then routes the effects by kind (until step 15). The precombat-main body puts each ability on the stack as one object (CR 603.3); one Oracle ability is one `addTrigger` of all its effects (Abstract Paintmage, Sanctum of Stone Fangs). Code that only inspects which effects a card has (cumulative upkeep, the conspiracy marker, the Oath active-player check, Wall of Nets) reads the raw effects (`Card.getTriggerEffects`). Planes are read through `PlanechaseService.step(game, StepTrigger...)`, which judges their step abilities' event conditions with `StepAbilityReader.triggering` too and hands each ability whole to the stack door with the planar object it is of (`sourcePlanarObject` on the record), as do its planeswalk, encounter and chaos readers (the event condition judged per ability, `MiscAbilityReader` rejecting what they can't read). Spells, land plays and activations have real triggers as well: `SpellTrigger` (cast, "cast this spell", copied, counters, countered, "this spell is countered or fizzles"; CR 601.2i), `LandPlayTrigger` (CR 116.2a) and `AbilityTrigger` (activated, non-mana, exhaust, embalm or eternalize, "a mana ability of this resolves"), built by named `Triggers` factories (`youCastSpell()`, `opponentCastsSpell()`, `youCastThisSpell()`, `youPlayLand()`, `youActivateNonManaAbility()`, …). They aren't rules events either: the spell-cast, copy, counter, land-play and activation collectors in `TriggerCollectionService` still run where the slots were collected, reading the abilities through `SpellAbilityWatch` (one constant per old slot, naming its trigger and the zone the collector reads, and `dispatchWatch`), and each hands the ability whole to the stack door. No spell, land-play or activation ability has a legacy view (`SpellAbilityWatch.effectsOf` throw for them), so every reader reads the ability itself. An unfiltered one (no spell filter, land filter or zone) is collected by `TriggerCollectionService.collectUnfilteredAbility`, which checks the event condition as it triggers and hands the ability to the stack door with the event's record (`spellWatchRecord`: the land played and the player who played it, the mana ability's activator and the mana it produced, the countered spell), the door judging its intervening "if" and limit; the "when you cast this spell" and "when this spell is countered" readers and the suspended-card reader do the same. The "when you cast this spell" reader puts the card's own and perpetually granted abilities through the stack door (`putSelfCastAbility`) and the engine's granted replicate and demonstrate through `collectSelfCastAbilities`, each as one object (CR 603.3), and records the spell (its X, kick, cast zone and the spell itself) as the entry's triggering spell whatever the effects are; a "you may" is asked as it resolves (CR 603.5). A cast trigger with `.grantedToTheSpell()` ("spells you cast … have cascade") is the spell's ability: each effect its own object sourced by the spell, never triggered additional times. A granted ability with a limit is the granting permanent's instance of it (`TriggeredAbility.instance()`, set by `GrantTriggeredAbilityEffectHandler`), so each grant keeps its own limit (CR 113.2c). The activation collectors read every activation ability itself (`TriggerCollectionService.activationAbilities`, by `AbilityTrigger.unfiltered()`): `activationTriggers` judges the trigger's ability kind (`youActivateAbility().withKind(AbilityTrigger.AbilityKind.LOYALTY)`, `AbilityKind.matches(ActivatedAbility)`) and source filter (`.withSource(permanentPredicate)`, from the watcher's point of view) and the event condition, and the stack door the limit and the intervening "if" ("if mana from a Treasure was spent to activate it", an `EventFactCondition` the context carries, judged once). A land-play trigger's filter or zone (`youPlayLand().withFilter(cardPredicate)`, `.playedFrom(Zone.EXILE)`, `.notPlayedFrom(Zone.HAND)`) makes it its own `watchKey()` too: the land-play watches' dispatch (`dispatchSpellWatch`, and the planar reader) hands the ability to `PlayedCardNameTriggerCollectorService.collectLandPlayAbility`, which judges the filters and the event condition and hands the ability to the stack door, the player who played the land as "that player" and the land as the triggering card, its targets chosen as it goes on the stack. A cast trigger's `SpellFilter` (`youCastSpell().withFilter(cardPredicate).withStackEntryFilter(…).duringYourTurn().nthThisTurn(2)…`, or `.anySpell()`) marks an ability the generic spell-cast collector reads itself, not through the legacy view: a filtered `SpellTrigger` is its own `watchKey()`, and the cast watches' dispatch (`TriggerCollectionService.dispatchSpellWatch`, and the exile, graveyard, hand, command-zone and planar readers) hands it to `SpellCastTriggerCollectorService.collectCastAbility` as a `CastAbility` (the filter and the ability), which judges the filter and the event condition and hands the ability to the stack door: one stack object of its effects as written (CR 603.3), a "you may" or "you may pay" asked as it resolves (CR 603.5) and the targets of what it offers chosen as it goes on the stack (`MayEffect` and `MayPayManaEffect` give the offered effect's `targetSpec`, CR 603.3d), its limit and intervening "if" judged by the door. The dispatch reads the filter through the permanent's text changes (`TextChangeTransformer.transformSpellFilter`). The filter also names the zone the spell was cast from (`.castFrom(zone)` / `.notCastFrom(zone)`, judged from the cast event's zone; the spell counts then count that zone's spells), a kicked spell (`.kicked()` / `.eachKick()`, the kick count the stack entry's event value) and whose spells the counts count (`.countingEveryPlayersSpells()`). A copy trigger's filter (`youCopySpell().withFilter(…)`, spell and stack-object conditions only) is read the same way (`collectCopyAbility`, every spell type); those collectors take a missing target filter from the bound target group too. A cast trigger without a filter is still collected by its effect's class (the effects that bind the spell or its caster, until step 15). No collector unwraps a "you may" to find a handler: `TriggerCollectorRegistry.dispatch` picks a handler by the effect's own class, then the watch's default (the creature-death watches and the source's own zone changes have only their default), so a `MayEffect`, `MayPayManaEffect` or `MayPayTapPermanentsEffect` around a class-keyed effect reaches only a handler registered for the may class itself (CR 603.5: the option is the ability's, asked as it resolves). A cast ability's "while …" (`TriggerOptions.withEventCondition`, `CastAbility.eventCondition`) is checked only as the spell is cast (CR 603.2), never again as the ability resolves. A temporary global cast trigger with a spell filter ("until end of turn, whenever you cast an instant or sorcery spell, copy it") is collected by the generic cast collector too. Granted abilities are found by their trigger's `watchKey()` too (`TriggeredAbility.hasWatchedTrigger`). Combat triggers have a real `CombatTrigger` (a `CombatEvent`: attacks, attacks you, one or more attack, attacks and isn't blocked, blocks, becomes blocked, combat damage to a player, creature, planeswalker, battle, you, its owner, …; an `ObjectRelation` for whose creature: `THIS`, `YOU_CONTROL`, `ANY`, `EQUIPPED`, `ENCHANTED`, `OPPONENT_CONTROLS`; and an optional filter), built by named factories (`Triggers.attacks()`, `creatureYouControlAttacks()`, `youAttack()`, `blocks()`, `becomesBlocked()`, `attacksUnblocked()`, `dealsCombatDamageToPlayer()`, `creatureYouControlDealsCombatDamageToPlayer()`, …; CR 508.1, 509.1, 510.2). They aren't rules events either: the attack, block and combat damage collectors in `CombatAttackService`, `CombatBlockService`, `CombatDamageService`, `CombatTriggerService` and `TriggerCollectionService` still run where the slots were collected, reading the abilities by `CombatWatch` (one constant per old slot; `SpellAbilityWatch` and `CombatWatch` are `TriggerWatch`es) through `CombatAbilityReader`, and their handlers are keyed with `@CollectsCombatTrigger`. A combat ability carries no trigger-only wrapper: a restriction on the creature is the trigger's filter (`Triggers.creatureYouControlAttacks().withFilter(p)`, `becomesBlocked().withFilter(p)` for the blocker; `CombatTrigger.watchKey()` drops it but for the same-name and goaded filters, whose collectors read them), the intervening "if" and the limit are `TriggerOptions`, "blocks" once each combat and "one or more creatures deal combat damage" are `TriggerMultiplicity.ONE_OR_MORE` and "becomes blocked by a creature" is `EACH_BLOCKER` (CR 509.3a, 509.3d), and "attacks or blocks" is one ability with both triggers (`Card.addTrigger(List.of(...), options, effects)`). A combat ability has no legacy view (`CombatWatch.effectsOf` / `registrationsOf` throw for it): every collector reads the abilities (printed by `CombatAbilityReader.printed(card, watch)`, granted by `temporary` / `persistent` / `GrantedTriggeredAbilitySupport.grantedWatchedAbilities`, a registered one by `TemporaryGlobalTriggeredAbility.ability()`, a graveyard card's by `GameQueryService.getEffectiveGraveyardTriggeredAbilities`) and `CombatAbilityReader.read` gives each effect as a `CombatEffect` with its ability's filter on the creature (the one the watch key drops), limit (marked by `TriggeredAbility.limitKey()` on the source; "attacks for the first time each turn" is `ONCE_EACH_TURN`, judged by the attack count) and multiplicity, which the collector judges itself; the ally combat damage collectors read the abilities' filter and "one or more" from the ability and record the creature that dealt the damage as the stack entry's triggering permanent (its creatures as the triggering permanents for "one or more"), which "it" / "that creature" reads, and `CombatAbilityReader.effects(abilities, trigger)` serves a collector that reads no filter, limit or multiplicity, throwing on one. The collectors judge the intervening "if" and the event condition from the ability as it triggers (`ConditionEvaluationService.triggerConditionsMet`, or a `TriggerJudge` on the abilities a reader flattens), in the context of their event; the intervening "if" also wraps each effect as the `ConditionalEffect` that checks it again as it resolves, and the event condition is never checked again; code that only inspects a combat ability's effects reads `CombatAbilityReader.rawEffects`. A multiplicity no combat collector reads ("one or more" on an attack, "each blocker" off "becomes blocked", "each source" off a damage trigger) is rejected as the `TriggeredAbility` is built. Each combat ability is one object on the stack (CR 603.3): `CombatAttackService`'s attack collectors read one list per ability (`CombatAbilityReader.readByAbility`) and put each ability, printed, granted or temporary, on the stack as one object of all its effects (`effectsAsJudged`), and the attached-permanent collector one object per ability; there is no trigger mode. On an Aura or Equipment the `THIS` attack, block, becomes-blocked and combat-damage-to-a-player triggers are the attached creature's, as the slots were. Damage triggers, combat or noncombat, have a real `DamageTrigger` (a `DamageEvent`: deals damage, to a player, opponent, you, creature or planeswalker, noncombat, an instant or sorcery's, one or more creatures'; is dealt damage, noncombat or excess damage (CR 120.10); you, an opponent or enchanted player is dealt damage; damage to you is prevented (CR 615.1); and an `ObjectRelation` for the source, or for the damaged permanent of an "is dealt damage" event), built by named factories (`Triggers.dealsDamage()`, `dealsDamageToPlayer()`, `dealtDamage()`, `enchantedCreatureDealtDamage()`, `creatureYouControlDealsDamageToCreature()`, `youAreDealtDamage()`, `sourceYouControlDealsDamageToOpponent()`, …; CR 120.1). They aren't rules events either: the damage collectors in `TriggerCollectionService`, `DamageSupport` and `CombatDamageService` still run where the slots were collected, reading the abilities through `DamageWatch` (a `TriggerWatch`, one constant per old slot), and their handlers are keyed with `@CollectsDamageTrigger`. A damage ability carries no trigger-only wrapper: a restriction on the permanent is the trigger's filter (`Triggers.permanentYouControlDealtDamage().withFilter(p)`: the damaged permanent for an "is dealt damage" event and for "this deals damage", the dealer for the other "deals damage" events; `DamageTrigger.watchKey()` drops it), the intervening "if" and the limit are `TriggerOptions` (with `TriggerLimit.ONCE_EACH_TURN_FOR_EACH_CREATURE` for Stensia), "whenever a source deals damage to this" is `TriggerMultiplicity.EACH_SOURCE` (CR 603.2c), and one Oracle ability over several damage watches is one ability with all their triggers. A damage ability has no legacy view: every `DamageWatch` collector, for printed, granted, persistent, graveyard, planar and registered abilities alike, reads it through `DamageAbilityReader` (the finders are `WatchedAbilities`'), judging the filter against its own permanent (the source, each dealer, the damaged permanent) with the watcher as the ability's source, the limit by `TriggeredAbility.limitKey()` (or for the plane and the creature, Stensia), and "each source" by splitting the event per source; the intervening "if" is judged from the ability as the dispatch reads it, with the damage dealt. The self-deals-damage snapshots (`PendingSourceDamage`, `CombatDamageState`) hold the abilities, not effects. On an Aura or Equipment the `THIS` deals-damage-to-a-player and to-an-opponent triggers are the attached creature's, as the slots were. Counter triggers have a real `CounterTrigger` (a `CounterEvent`: counters, +1/+1, -1/-1, loyalty, time or lore counters put or removed, by anyone or by you or an opponent, once per permanent or once per counter; becomes renowned or monstrous, evolves, trains, a Class reaches level 2 or 3, you get energy, you proliferate; an `ObjectRelation` for the permanent the counters are put on or removed from; and a filter for its type: a creature, a Human, a Hero, a non-Hydra creature, a planeswalker, a Saga), built by named factories (`Triggers.countersPutOnThis()`, `plusOneCountersPutOnThis()`, `plusOneCountersPutOnCreatureYouControl()`, `youPutCountersOnCreature()`, `minusOneCountersPutOnCreature()`, `becomesMonstrous()`, `youProliferate()`, …; CR 122.1, counters a permanent enters with included, CR 122.6). `timeCounterRemovedFromThisInExile()` functions from exile by default. They aren't rules events either: the counter collectors in `TriggerCollectionService`, `PermanentCounterSupport` and the counter effect handlers (train, evolve, Class level up) still run where the slots were collected, reading the abilities through `CounterWatch` (a `TriggerWatch`, one constant per old slot), and their handlers are keyed with `@CollectsCounterTrigger`. A counter ability carries no trigger-only wrapper: a further restriction on the permanent is the trigger's filter (`CounterTrigger.withFilter(p)`, its `qualifier`), the intervening "if" and the limit are `TriggerOptions`, and the "you put counters on a creature you control", "you put +1/+1 counters on this", "you remove a time counter from this card while it's exiled" and "a +1/+1 counter is put on this" (each counter) events are read by the collectors of the event about any player (`CounterTrigger.watchedEvent()`, part of `watchKey()`). A counter ability has no legacy view (`CounterWatch.effectsOf` / `registrationsOf` throw for it): every collector, for printed, granted (Danny Pink), graveyard and exiled abilities alike, reads it through `CounterAbilityReader` (the finders are `WatchedAbilities`'), which gives each effect as a `CounterEffect` with its ability's filter on the permanent (the `qualifier`), its own event (`byController()` for "you put" / "you remove", `eachCounter()` for "a +1/+1 counter is put on this", once for each counter) and its limit, judged and marked by `TriggeredAbility.limitKey()` on the source (or for the source and the creature, `ONCE_EACH_TURN_FOR_EACH_CREATURE`; "do this only once each turn" marked as the action is taken); the strict `printedEffects` / `effects` / `registrations` serve the collectors that judge none of them and throw on one, and the collectors reached through `dispatchWatch` (energy, proliferate, counters removed, time and lore counters put) judge only the limit. The collectors judge the event condition from the ability as it triggers, in the context of their event, and hand it to the stack door (`putTargetAbility`), which judges the intervening "if" and the limit and wraps the effects for the check as it resolves; the event condition is never checked again. A multiplicity other than once for each event is rejected as the `TriggeredAbility` is built. The "becomes monstrous" and exiled time-counter collectors hand their handlers every effect they read in the trigger context, put on the stack as one object. Becomes-the-target triggers have a real `TargetTrigger` (a `TargetEvent`: becomes the target of a spell, an Aura spell, an instant or sorcery spell, an opponent's spell, a spell or ability, an opponent's spell or ability (ward, CR 702.21a), your spell or ability, an activated ability (one or more, once per ability) or a backup ability; you, or you or a permanent you control, become the target; a player chooses targets; an `ObjectRelation` for the permanent that becomes the target; and a filter for its type), built by named factories (`Triggers.becomesTargetOfSpell()`, `becomesTargetOfSpellOrAbility()`, `becomesTargetOfOpponentSpellOrAbility()`, `creatureYouControlBecomesTargetOfOpponentSpellOrAbility()`, `youBecomeTargetOfSpell()`, `playerChoosesTargets()`, …; CR 601.2c, 602.2b). They aren't rules events either: the becomes-the-target and target-choice collectors in `TriggerCollectionService` still run where the slots were collected, reading the abilities through `TargetWatch` (a `TriggerWatch`, one constant per old slot); the family had no handlers. A becomes-the-target ability carries no trigger-only wrapper: a restriction on the permanent is the trigger's filter (`TargetTrigger.withFilter(p)`, its `qualifier`), the intervening "if" and the limit are `TriggerOptions`, and "this becomes the target of a spell [or ability] you control" (`becomesTargetOfYourSpell()`, `becomesTargetOfYourSpellOrAbility()`) and "a player or permanent becomes the target of an ability you control" (`playerOrPermanentBecomesTargetOfYourAbility()`) are read by the collectors of the event about anyone (`TargetTrigger.watchedEvent()`, part of `watchKey()`). A becomes-the-target ability has no legacy view (`TargetWatch.effectsOf` / `registrationsOf` throw for it): every collector, for printed abilities, abilities granted to the permanent (`WatchedAbilities.temporary` / `persistent`) and abilities a static ability grants (`GrantedTriggeredAbilitySupport.grantedWatchedAbilities`) alike, reads it through `TargetAbilityReader`, which gives each effect as a `TargetEffect` with its ability's filter on the permanent (the `qualifier`, judged by the collector against the targeted permanent), its own event (`byController()` for "a spell [or ability] you control" and "an ability you control") and its limit ("triggers only once each turn", "for the first time each turn", judged and marked by `TriggeredAbility.limitKey()` on the source); the strict `printedEffects` / `effects` / `grantedToPermanentEffects` serve the collectors that judge none of them and throw on one. The collectors judge the intervening "if" and the event condition from the ability as it triggers (`ConditionEvaluationService.triggerConditionsMet`, or a `TriggerJudge` on the abilities a reader flattens), in the context of their event; the intervening "if" also wraps each effect as the `ConditionalEffect` that checks it again as it resolves, and the event condition is never checked again. "One or more" is rejected as the `TriggeredAbility` is built. "Of a spell or ability an opponent controls" on this permanent is ward's trigger whatever its effect: the non-counter collector reads the abilities granted to the permanent too. A triggered ability that another permanent granted names that permanent (`TriggeredAbility.grantingPermanentId()`): the static grant handler names the Aura or Equipment of an "enchanted / equipped creature has '…'" grant as the layer system grants it (`GrantTriggeredAbilityEffectHandler`), and a one-shot grant (`GrantEffectToTargetUntilEndOfCombatEffect`) names the resolving ability's source; a delayed combat-damage watch (`RegisterDelayedWatchedCreaturesCombatDamageEffect`, `DelayedWatchedCreaturesCombatDamage.creatingPermanentId`) names the registering ability's source on each of its triggers' entries, though that ability is the registering permanent's own delayed trigger (CR 603.7e), not an ability of the watched creature. The collector that puts the ability on the stack copies it to the entry (`StackEntry.setGrantingPermanentId`, read from the ability the collector routes), a "you may" carries it through `PendingMayAbility.grantingPermanentId`, and the effects that name the granting permanent ("sacrifice this Equipment", "transform Optimus Prime", "other than Animal Friend", `SacrificePermanentThenEffect`'s granting-permanent forms, `BecomePreparedEffect.ofGrantingPermanent()`) read it there with `StackEntry.requireGrantingPermanentId()`, which throws when a collector dropped it. No collector rebuilds an effect with the granting permanent bound in.

A damage-to-a-player trigger's "that player" — "target creature that player controls", "destroy target land that player controls" — is the player the event was about, never bound into the effect (the damage-to-a-player collectors' record, `TriggerCollectionService.playerDamageRecord`, names the damage, the player, the source and its controller whatever the effects are, the player also as the attacked target a "that player controls" target is judged against; for "a source an opponent controls deals damage to you" the non-targeting "that player" is that opponent): the door's `PermanentChoiceContext.AttackTriggerTarget` carries that player from the record, `TriggerTargetCollector` puts it in the filter context (`FilterContext.triggeringPlayerId`) that `PermanentControlledByTriggeringPlayerPredicate` reads, and the stack entry built from the choice keeps it (`StackEntry.triggeringPlayerId`) for the resolution recheck (`TargetLegalityService`, `TargetValidationContext.triggeringPlayerId`). Every damage-to-a-player collector (the combat damage service's own, attached, curse, ally and equipped readers, the noncombat `putDealsDamageToPlayerAbility`) records the event the same way whatever the effects are: the player dealt damage as the entry's triggering player and, when no target is chosen, its non-targeting `targetId`, the damage as its event value, and on an Aura's, Equipment's or Curse's ability the creature that dealt it as its triggering permanent (the ability's source stays the Aura or Equipment). A player-targeting effect the card declares no `target(...)` for is "that player" (a card printing "target opponent" declares it: Brash Taunter, Daredevil, Fearless Fighter); the triggered modal, its modes chosen as it is put on the stack or as it resolves, and the reflexive "when you do" abilities (`QueueReflexiveAbilityEffect`, `RemoveCounterFromSourceThenEffect`) reuse the entry's player by the same rule. No effect tells the collectors what to record (the `CombatDamageTriggerContextEffect` interface is gone). "Of that player's choice" on a combat damage trigger is the card's `combatTriggerTargetChosenByDefendingPlayer`. A reflexive "when you do" ability's "that player" (Dokuchi Silencer, CR 603.12) is the triggering player of the entry that created it: the combat damage collector gives a non-targeted "you may" entry the player dealt damage, `DiscardCardThenEffectHandler` gives its `DiscardFollowUp` the entry's triggering player (`withTriggeringPlayer`), the reflexive target is chosen and validated with it (the filter context, `TargetLegalityService.validateActivatedAbilityTargeting`'s triggering-player overload) and its `PermanentChoiceContext.MayAbilityTriggerTarget` (`withTriggeringPlayer`) gives it to the reflexive entry. A `SpellTargetTriggerAnyTarget` with a triggering player judges its target filter with it (Chandra's Incinerator's "that player controls" on noncombat damage to an opponent). A linked ability's "the exiled card" (Hoarding Dragon, CR 607.2a) is the stack entry's linked exiled card (`StackEntry.linkedExiledCardId`), set by the death collector from the source's imprint as the ability triggers, so the source returning and exiling another card can't redirect it. A death trigger's "another target card" is judged against the source's own physical card (its snapshot's original card), so a copy excludes itself rather than the card it copied. A discard trigger's "they" and "that card" (Gutmorn, Pactbound Servant) are the discarding player and the card discarded, which the discard default records on its entry (`StackEntry.triggeringPlayerId`, `setTriggeringCards`); the land-play default records the land played as the triggering card the same way.

A damage-to-a-permanent trigger records its event the same way whatever the effects are: "whenever this is dealt damage" (and "… noncombat damage"; `TriggerCollectionService.collectDealtDamageAbilities`) the damage as its event value (and X), the source of the damage as its triggering permanent with that source's controller as it dealt the damage, and the damaged permanent's last known information with its damage keywords as its source snapshot; "whenever a [filtered] creature is dealt damage", "a permanent you control is dealt damage" and "a source you control deals noncombat damage to a creature" (`damagedPermanentRecord`) the damaged permanent as the triggering permanent with its controller and last known information, and the damage; every one is handed to the stack door, which chooses a target as it goes on the stack. "That permanent or player" of a recipient ability (Ghyrson Starn) is the record's non-targeting target, dealt damage by `DealDamageToAnyTargetEffect.toEventObject`, which targets nothing; a declared "any target other than that permanent" (Toralf) reads `PermanentIsTriggeringPermanentPredicate`. The combat damage step reads its "is dealt damage" abilities as the damage is dealt and puts them on the stack, once its creatures have died, through the same default (`TriggerCollectionService.collectDealtDamageAbilities`, with the damaged permanent's last known information in `TriggerContext.DamageToCreature.damagedLastKnown`), so the limits, intervening "if"s, event conditions and additional-trigger effects (Roaming Throne) apply alike; the event conditions see the source as the triggering permanent and its controller as "that player" (Archfiend of Spite's "a source an opponent controls" is `NotCondition(TargetPlayerIsController())`). Damage of 0 isn't dealt and triggers nothing (CR 120.8).

A block or "becomes blocked by a creature" trigger's "that creature" — the creature on the other side of the block — is never chosen by the effect's class: the block collectors (the blocker's own and effect-made blocks, `CombatBlockService`), the "becomes blocked by a creature" collector (printed, granted and continuously granted abilities with `EACH_BLOCKER` or a filter on the blocker) and the Aura and Equipment readers (`CombatTriggerService`) record it on the entry whatever the effects are: as its triggering permanent (id, controller, last-known copy) and non-targeting `targetId`, with its power and toughness as the ability triggered (an Aura's or Equipment's entry keeps the enchanted or equipped creature as its triggering permanent and the other creature as its `targetId`). A permanent or player target the card declares (`target(...)`, Elite Javelineer) is chosen as the ability goes on the stack; one it doesn't declare is that creature (CR 115.10a). A "[filter] creature" is the trigger's filter (`Triggers.blocks().withFilter`, `Triggers.becomesBlocked().withFilter`), judged as the creature blocks or becomes blocked (CR 509.3f): on the creature it blocks, or with `ONE_OR_MORE` any creature it blocks; for each blocker with `EACH_BLOCKER`, and without it ("becomes blocked by one or more") once if any blocker matches. No effect tells the collectors to do this (the `CombatOpponentReferencingEffect` interface is gone). A "whenever a [filter] creature (you control) becomes blocked" watcher (`CombatBlockService`'s ally and any-creature readers) is the ability's source (CR 113.7) and records the blocked creature as its triggering permanent (id, controller, a last-known copy) and non-targeting target whatever the effects are, so "it" is a triggering-permanent reference, never a self effect with a rebound source; "becomes blocked by a creature" there (`EACH_BLOCKER`, No Quarter, Righteous Indignation) is once per declared pair, the blocker its target and the pair's comparison its event condition. A "whenever you attack" entry records its attacking creatures whatever the effects are (the band's for `TriggerMultiplicity.EACH_BAND`), and "they gain …" is `GrantScope.DECLARED_ATTACKERS`; an Equipment's own "whenever equipped creature attacks, choose one" (Pip-Boy 3000) is its controller's, an ability granted to the creature its controller's (CR 113.8).

Every step and phase reader of `StepTriggerService` (your, each, each opponent's and the chosen player's upkeep, the Aura's and Curse's upkeep, draw step and end step, precombat, postcombat and second main phase, beginning and end of combat, and the command-zone, graveyard and exile readers), the emblems' step reader and the planar readers judge only each ability's event condition (`StepAbilityReader.triggering`, which rejects a multiplicity or limit no step reads) and hand the ability whole to the stack door with the record of the step (`putStepAbility`); the door judges the intervening "if", "only once", the doublers and the routes. "That player" of a cast trigger is the caster, the non-targeting entry's `targetId` the `TRIGGERING_PLAYER` recipients read, and "the same name as that spell" is `CardSharesNameWithTriggeringSpellPredicate`, which the `CardsInGraveyard` count reads from the entry's triggering spell. "Counter that spell" is `CounterSpellEffect` (or `CounterUnlessPaysEffect`) on a filtered cast trigger, which the stack door aims at the triggering spell on a non-targeting entry (Chalice of the Void's and Void Mirror's conditions stack-entry filters, Cephalid Shrine's count read as it resolves); an effect that exiles "it" or has "that player" choose (Knowledge Pool, Possibility Storm, Eye of the Storm, Ice Cave's payment) reads the spell, the caster and the source permanent from the entry as it resolves. "Copy it for each other instant and sorcery spell you've cast before it this turn" (Thousand-Year Storm) is `CopyTriggeringSpellEffect().withCopies(new SpellsCastBeforeTriggeringSpellThisTurn(filter))`, counted as it resolves up to the triggering spell's place among its caster's spells this turn, which the cast collector keeps on the entry (`StackEntry.triggeringSpellCastIndex`). Storm (`CopyTriggeringSpellEffect.storm()`, CR 702.40a) counts every player's spells before the triggering spell the same way, up to its place in the turn's cast order (`StackEntry.triggeringSpellTurnCastIndex`); the self-cast collector records the triggering spell, both places and its X and repeatable additional cost payments on every "copy this spell" entry, so replicate's, gravestorm's and the other counted copies' amounts read them as the ability resolves. A cast trigger's record names the caster as its triggering player, which its parked target choice carries, so "another target player" (`PlayerOtherThanTriggeringPlayerPredicate`, The Lord of Pain) is judged against the caster as the target is chosen and against the entry's triggering player as it resolves. A spell's own "whenever this spell is countered or fizzles" ability (Trial and Error) has the spell as it last existed on the stack as its triggering spell. A spell-copy trigger's "that spell" is the copy the event was about: the copy collector's record names it as the entry's triggering spell, the copying player as "that player" and the copy's mana value as the event's value (Parnesse, the Subtle Brush's `CopyCopiedSpellForTargetPlayerEffect`).

A becomes-the-target trigger's "that spell or ability" and "its controller" are the stack entry's triggering spell, never chosen by the effect's class: every becomes-the-target collector hands the ability to the stack door through `TriggerCollectionService.putTargetAbility`, whose record (`recordTargetingObject`) names the spell or ability that targeted as the entry's triggering spell (a copy as it was then, read live while it is on the stack and as it last existed there once it has left, CR 608.2h, through `CopySupport.triggeringSpell`) and its controller as the triggering player, whatever the effects are, with what the collector's event names besides ("that creature" as a non-targeting `targetId` or the triggering permanent, "that player"). The door aims an effect that acts only on a spell or ability ("counter that spell or ability unless its controller pays", ward) at that object on the stack without targeting it when the record names no object but a player; ward is identified by that rule, not by a counter class. The door counts "if a creature you control becoming the target … causes a triggered ability of a permanent you control to trigger, it triggers an additional time" (Valiant Emberkin) from the request's event (`TriggerContext.BecomesTarget`) beside every other doubler. Pawpatch Recruit's "other than that creature" and Scalelord Reckoner's "that player controls" are their target filters (`PermanentIsTriggeringPermanentPredicate`, `PermanentControlledByTriggeringPlayerPredicate`). "For the first time each turn" is the trigger's `TriggerLimit.FIRST_TIME_EACH_TURN` (Glyph Keeper). A delayed triggered ability an activation creates is the activator's (CR 603.7e) and independent of its source's abilities: Giant Oyster's activation queues a `DelayedDrawStepTriggerWhileSourceTapped` (read by `StepTriggerService` at each of that player's draw steps, ended when the source untaps or leaves) and a `DelayedSourceUntapsOrLeavesTrigger` (put on the stack by `UntapLockReleaseService`).

A triggered ability's "its counters", "that creature's name", "its mana value", "that artifact", "the Auras attached to it" — the last-known information of the permanent a death, departure or sacrifice was about — is the stack entry's triggering permanent (`StackEntry.setTriggeringPermanent(lastKnown, attachments)`, a copy of the event's battlefield snapshot, CR 603.10a), set by the collector that puts the ability on the stack, never bound into the effect: effects read `getTriggeringPermanentSnapshot()`, `getTriggeringAttachments()`, `triggeringPermanentCounters()` / `triggeringPermanentCounterCount(type)` as they resolve, and an amount reads it through `CountersOnTriggeringPermanent`; a predicate that compares with "it" or its controller reads `FilterContext.triggeringPermanentId` while that permanent is on the battlefield and `FilterContext.triggeringPermanentSnapshot` once it has left (`PermanentSharesCardTypeWithTriggeringPermanentPredicate`, `PermanentControlledByTriggeringPermanentControllerPredicate`; the snapshot is set by `SacrificePermanentsEffectHandler`, the id by `TriggerTargetCollector` and the resolution recheck in `TargetLegalityService`), never a source snapshot rebound to the triggering permanent. A trigger whose targets are chosen as it goes on the stack carries it through `DeathTriggerTarget.withTriggeringPermanent`, `SelfTriggeredAbilityTarget.withTriggeringPermanent`, `EntersTriggerTarget.withTriggeringPermanent` or `SpellTargetTriggerAnyTarget.withDepartedPermanent`. Every field that records the trigger event (the triggering permanent, card, cards, spell, player, the event value and payloads) is copied by `StackEntry.copyTriggerEventFrom`, which the copy constructor (and so the simulation copy) and `CopySupport.createCopyStackEntry` for a copied activated or triggered ability both call, so a copy of an ability reads the same trigger event (CR 707.10); a new trigger-event field goes there, not into the copy constructor alone. A damage trigger's "that source" is the triggering permanent too (`setTriggeringPermanentId`, with `setTriggeringPermanentControllerId` for the source's controller as it dealt the damage; a spell source has only the controller) and the damage its event value: "that source's controller" is `GameQueryService.findTriggeringPermanentController` — the current controller while the source is on the battlefield, otherwise the last known one (CR 608.2h) — which the `TRIGGERING_PERMANENT_CONTROLLER` recipients read. The group an event is about — "them", "each of them", "one of them" — is the entry's triggering permanents (`setTriggeringPermanentIds`): the matching dealers of a `TriggerOptions.ONE_OR_MORE` combat damage batch, and the matching attackers of a filtered `Triggers.youAttack()`, whose entry also has them as its attacking snapshots (`TotalPowerOfControlledCreatures.declaredAttackers`, `BoostAllOwnCreaturesEffect.forDeclaredAttackers`) and as its declared `GrantScope.TARGETS` recipients; `EachPermanentScope.TRIGGERING_PERMANENTS` reads them. The tapped permanent of a tap trigger (with its last-known snapshot, Haunted One), the permanent an attachment's becomes-the-target ability watched (Fractured Loyalty) and the attacker of an "attacks you" trigger (whose `withFilter` the collector judges as the creature is declared an attacker) are the triggering permanent too; the card of a graveyard event is the entry's triggering card with its graveyard incarnation (`setTriggeringCard`), or for a batch its event cards with theirs — never an id bound into the effect.

Simultaneous death batches snapshot continuously granted abilities that trigger on a zone change, the permanent's own (`Triggers.dies(THIS)` and the like) or another's ("whenever a creature dies"), before moving any permanent. The snapshot preserves abilities supplied by a paired creature or another permanent dying in the same event and is cleared when that event ends.

`SourceCardInGraveyard` ("if this card is in your graveyard") reads the graveyard incarnation the stack entry keeps for its source card (`StackEntry.sourceCardGraveyardEntryVersion()`: the one the collector records with `setSourceGraveyardEntryVersion`, carried by a target choice such as `AttackTriggerTarget.withSourceGraveyardEntryVersion`, else the triggering card's when the source is the triggering card, as for "when this dies"), so leaving and reentering the graveyard cannot satisfy an older Bridge from Below ability (CR 400.7). No collector binds the version into the condition. The source card's stay and the triggering card's are two records: every "this card" effect (`ReturnSourceCard…`, `ExileSourceCard…`, `ShuffleSelfFromGraveyardIntoLibrary`, a `CardIsSelfPredicate` return, persist, `ForcedCostOrElseEffect`'s source check, …) reads `sourceCardGraveyardEntryVersion()`, and `getTriggeringCardGraveyardEntryVersion()` is only the stay of the card the event was about (the discarded, milled or dying card). Every collector of an ability of a card in a graveyard records its stay with `setSourceGraveyardEntryVersion` whatever the effects are, the may path carries it (`PendingMayAbility.sourceGraveyardEntryVersion`), and a graveyard target choice records a source card still in a graveyard as the ability goes on the stack. The discard collectors record the discard on every entry (`DiscardRecords.record`: the discarding player as triggering player and non-targeting target, the discarded cards as triggering cards with their stays in `eventCardGraveyardEntryVersions`, a lone card also as the triggering card, and a discard event's count as the event value), as the cards-put-into-a-graveyard collectors record their cards (`MiscTriggerCollectorService.recordCardsPutIntoGraveyard`). "Whenever a player cycles a card" has the same default (cycling discards the card, CR 702.29a), and a targeted discard or cycling ability's `DiscardControllerTriggerTarget` carries the record (`withDiscard`) into the entry it makes. The scry and surveil defaults record the player as triggering player (and an opponent's as non-targeting "that player"). The tap-for-mana watches have one default (`LandTapTriggerCollectorService`): the entry records the tapping player (triggering player), the tapped permanent (triggering permanent with its last-known snapshot), the produced mana colors and the source snapshot whatever the effects are; a triggered mana ability (`TapAbilityReader.isTriggeredManaEffect`, CR 605.1b) resolves at once through its effects' handlers (CR 605.4a), parked while the permanent's own mana choice is open when an effect `readsProducedMana()`; a targeted one goes to `SpellTargetTriggerAnyTarget` with the same record. Who taps and which permanent is the trigger (`youTapLandForMana()`, `enchantedLandTappedForMana()`, `youTapThisLandForMana()`, `opponentTapsPermanentForMana()`: `TapTrigger.judgedTapRelation()`), judged by the caller; "its controller adds" is the tapped permanent's controller (`TappedLandManaSupport.tappedPermanentController`), not the tapping player (Piracy).

Delayed graveyard returns use stack entries and `CardIdSetPredicate` with graveyard entry versions.

A graveyard target restricted by the trigger event is chosen as the ability goes on the stack, before its entry exists, so the restriction is read from the trigger record (the entry the collector built for the ability that chooses nothing, `GameData.queuedTriggerRecord(choice)`), never from an X of the choice and never in a rebuilt effect: `processNextSpellGraveyardTargetTrigger` evaluates the effect's mana value limit (`dynamicMaxManaValue(new EventValue())`, `TriggeringCardManaValue`) with the record as the amount's stack entry and gives the filter the record's event value (`CardManaValueEqualsEventValuePredicate`), and as the ability resolves the same amounts and predicate read the stack entry (`TargetValidationContext.eventValue`). A collector therefore gives a target or graveyard choice the X its record has, not the damage dealt or a mana value: an effect's "that much" is `EventValue`. A death trigger's collector evaluates the effect's `dynamicMaxManaValue` as the ability triggers (the dying object as it last existed as the amount's source) into `DeathTriggerTarget.graveyardTargetMaxManaValue`, which the entry keeps as `StackEntry.graveyardTargetMaxManaValue`.

A triggered ability's "if that land is a Forest" / "that creature's creature types" reads the triggering permanent as it is when the ability resolves, never a value bound as it triggered: once the permanent has left the battlefield, `PermanentRemovalService` has recorded its last-known characteristics on every stack entry it triggered (`StackEntry.triggeringPermanentLastKnownCard`, the layered types, subtypes and colors, CR 608.2h), which `EffectResolutionService` gives a `TriggeringPermanentHasSubtype` "if" or "instead" as its triggering card. Evolve's comparison is the intervening "if" `TriggeringPermanentHasGreaterPowerOrToughnessThanSource`, judged as the ability triggers and again as it resolves (departure snapshots for a creature that left). "That creature's power / toughness" is the amount `TriggeringPermanentPower` / `TriggeringPermanentToughness`: the triggering permanent's current value while it is on the battlefield, else the value the collector recorded as the ability triggered (a dying creature's last-known one), else its departure snapshot; an enter collector records the entering creature on the entry, never in a rebuilt effect (Archon of Redemption, Hamletback Goliath, Cream of the Crop). Likewise an enter trigger's "put counters on it", "it gets +X/+Y", "transform it", "attach this to it" and "become a copy of that creature" are effects the card writes reading the entry's triggering permanent (`PutCounterOnTargetPermanentEffect.onTriggeringPermanent`, `PermanentReference.TRIGGERING`, `GrantScope.TRIGGERING_PERMANENT`, the `ofTriggeringPermanent()` forms); the enter collector puts them on the stack as written. No effect asks the enter collector to bind the entering permanent as its target or source any more: graft, Agent's Toolkit, soulbond's other half, "it connives", "deals N damage to it" (`DealDamageToTriggeringPermanentEffect`), endure, the power branches, Madame Null, Mana Echoes, Eldrazi Mimic and the graveyard Auras and Equipment that return attached to "that creature" read the entry's triggering permanent as they resolve, and a "you may" goes on the stack and asks as it resolves (CR 603.5).

Divided damage assignments belong to the individual stack entry; copies retain their division
while offering legal replacement targets. Additional ETB abilities on token copies are abilities
of their own, so they keep their targets and resolution separate from the copied abilities (CR 603.3).

`CharacteristicState.meleeInstances` preserves multiple melee abilities. Each instance triggers
separately and counts players attacked by declared attackers, excluding planeswalkers and battles.

The exert decision happens during attack declaration (CR 701.43a): the attack collector asks a lone "you may" whose effect says it exerts as it attacks (`CardEffect.exertsAsItAttacks()`, the card's `SkipNextUntapEffect.exert()`) off the stack, and accepting it immediately exerts the creature
and puts the "when you do" the card writes after the exertion (`QueueReflexiveAbilityEffect`) on the stack as one reflexive ability, through the same route as any accepted option with no handler of its own. The exertion itself (`SkipNextUntapEffect` with `controllerStepOnly` on the source) fires "whenever you exert a creature" (`TriggerCollectionService.checkExertTriggers`) wherever it resolves. A modal reflexive ability's modes are chosen by one service whichever handler made the ability (`ReflexiveModalChoiceService.beginModeChoice`: "choose up to that many" is `TriggeredModalEffect.maximumChoices()`, read against the ability's record).

Separate next-spell-copy effects each create their own triggered stack entry.

Simultaneous spell-cast triggers retain their triggering spell identity. Trigger ordering (CR 603.3b) is one interaction for every batch: once no trigger is waiting for targets or a may choice, `TriggeredAbilityQueueService.beginTriggerOrder` (called from `AutoPassService` before priority and before each combat-trigger auto-resolution) asks each player in APNAP order whose unordered triggers include two or more non-equivalent ones to place them from the bottom upward via `ChoiceContext.TriggerOrder`. Entries are reordered only within the positions that player's batch already occupies. `StackEntry.triggerOrderChosen` marks every trigger that has been through ordering (and everything on the stack when the top resolves) so it never joins a later batch; it survives simulation copies. Players in `GameData.playersAutoOrderingTriggers` keep the order the triggers were collected in without a prompt — the test harness enables this for both players by default (`harness.setAutoOrderTriggers(player, false)` to test ordering).

Divided-damage, divided-prevention and divided-counter triggers (`DealDividedDamageEffect` with `etbAssignments` and no target restriction, `PreventDividedDamageEffect` with `etbAssignments`, `DistributeCountersAmongTargetsEffect` in `CHOSEN` mode with `etbAssignments` and no target restriction, e.g. Glint Weaver, and the death triggers' `DistributeCountersAmongCreaturesOnDeathEffect`, also inside a `MayEffect`, e.g. Jugan) that reach the stack without a division announce it before priority: `AutoPassService` calls `StackedDividedDamageTriggerService.announceNextDivision` right after `StackedModalTriggerService.announceNextMode`. The amount is evaluated against the stack entry, so a death trigger's total reads the dying creature (`CountersOnTriggeringPermanent`, `TriggeringPermanentPower`). Kuldotha Flamefiend's `SacrificeArtifactThenDealDividedDamageEffect` (also inside a `MayEffect`) announces its zero or more targets the same way (`StackedDividedDamageTargets.allowsNoTargets`; zero targets is `StackEntry.divisionAnnounced` with an empty division). Nothing staged before the ability triggered is taken over; a divided enter ability with a declared target group (Fury, Bogardan Hellkite, Verdurous Gearhulk) chooses its targets through that group and divides among them in `ETBTokenTargetService`. The targets and division are chosen by the ability's controller, or for Grand Ossuary by the dying creature's controller; otherwise the controller picks one to `maxTargets` targets (`MultiPermanentChoiceContext.StackedDividedDamageTargets`) and divides through `ChoiceContext.CounterDistributionAssignment` with `stackEntryId` set, which records the division on the existing entry via `StackEntry.announceDamageAssignments`. An entry with no legal target is removed (CR 603.3d).

Delayed damage triggers retain the watched permanent as their damage source. `StackEntry.damageSourceControllerId` preserves that source's controller independently from the delayed ability's controller when the source leaves the battlefield.

A delayed triggered ability belongs to the resolution that created it (CR 603.7a): `StackResolutionService.resolveTopOfStack` counts the stack objects that begin to resolve (`GameData.resolutionOrdinal`, copied for simulations and kept across a turn restart) and `GameData.queueDelayedAction` stamps each `DelayedAction` with it (`DelayedAction.scheduledBy`; `DelayedPermanentAction`, `ExilePermanentAtNextUpkeep` and `ExileToOwnerGraveyardAtNextUpkeep` keep it as `schedulingResolution`). A queue that puts several actions on the stack as one ability groups by the source card, the controller and that resolution (`PermanentRemovalService.processDelayedPermanentActions`, `StepTriggerService.queueDelayedPermanentExiles`, the two upkeep queues), so one resolution's "exile them at the beginning of the next end step" is one stack object and two resolutions of one source are two. The counted "when you next cast / activate ..., copy it" abilities are an entry per unit. A "when [source] leaves the battlefield or becomes untapped" ability is a `DelayedSourceUntapsOrLeavesTrigger` per resolution (Giant Oyster; Tawnos's Coffin, whose effect is `ResolvePendingExileReturnEffect`). `scripts/step15-run17z17d-scan.py` lists every delayed queue and how it groups.

`DelayedZoneChangeTrigger` registers a one-shot watch on a permanent's identity and maps its departure destination to an existing effect. It is independent of that permanent's abilities, so Earthbend returns survive ability removal. Every departure consumes the watch, including destinations without an effect. The triggered entry stores the departed card's identity; graveyard entry versions bind after the card reaches the graveyard and prevent an old trigger from returning a later incarnation.

Controller end-step abilities with explicitly bound target groups use the existing mixed-target trigger continuation for permanent, player, and graveyard groups. Graveyard candidates pass both the group's card predicate and the bound effects' shared target validators before being offered. Life gained or lost restrictions use the triggered ability's controller even if its source changes control or leaves before resolution.

Generic triggered-ability doublers include their last-known simultaneous death snapshots when
collecting abilities caused by those deaths.

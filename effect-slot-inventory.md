# EffectSlot inventory

Step 1 of [effect-slot-refactor.md](effect-slot-refactor.md): one row per `EffectSlot` constant. Generated by `scripts/effect-slot-inventory.py` at `2138409bdd`; do not edit it by hand. The kind, step, event, object, relation, zone, multiplicity, self, grouping and notes columns come from `scripts/effect-slot-classification.tsv`, which is kept by hand and was checked against the collectors. Everything else is read from the sources on every run.

Re-run `python3 scripts/effect-slot-inventory.py` after a step moves slots (add `--results` after a full card-test run to refresh the baseline), and update the TSV when a slot changes behaviour. `--gradle-args <step>` prints the Gradle arguments that run the card test classes of a step's cards, one `--tests` filter per class after each module's test task.

## Columns

- **Kind**: spell, static, activated, mana, replacement, special action, marker or triggered (CR 113.3). A slot that mixes kinds is listed under its main kind; its notes name the rest.
- **Step**: the refactor step that moves the constant. 13.x is row x of step 13's table.
- **Event**, **Object**, **Relation**: what happens, the type filter on the object it happens to, and who that object or player is relative to the source and its controller, as the code checks them.
- **Zone**: where the source has to be for the ability to work.
- **Mult.**: how often one event triggers it: per object, per event (one or more), per counter, ….
- **Self**: whether the source's own event triggers it: only, yes, no, heuristic, or n/a.
- **Grouping**: how the readers turn several registrations of the slot on one card into stack objects. *each*: one stack object per registration. *all*: one stack object for all of them. *all-but-independent*: one shared object, plus one for each `TriggerMode.INDEPENDENT` registration. *split*: partitioned some other way (see notes). *none*: never put on the stack. *varies*: the readers disagree (see notes).
- **Cards**: card classes in `magical-vibes-card` that name the constant.

The details under each table give, per constant:

- **Readers**: every method in engine, domain, AI, networking and engine test-fixture main code that names the constant (`EffectSlot.X`, a `@CollectsTrigger` slot, a `case` of a `switch` on a slot, or a `slot.name()` prefix test), by class, with a guess from the method body: *each* (dispatches each registration through the registry or queues `List.of(effect)`), *all* (queues the whole list), *mode* (reads `TriggerMode.INDEPENDENT`), *mixed* (both), *read* (does not queue), *queue?* (queues, shape unclear). The Grouping column is the reviewed answer. A handler gets one registration at a time from `TriggerCollectorRegistry`, so it is listed with the effect class it is registered for. Methods that walk `EffectSlot.values()` are listed once, under [Readers of every slot](#readers-of-every-slot).
- **Wrappers**: trigger-level wrapper effects (`May…`, `…Conditional…`, `Once…`, `SequenceEffect`, `ChooseOne…`) in the card registrations, with counts. **Trigger effects**: `…TriggerEffect` classes. **Aware**: `…AwareEffect` interfaces that the slot's readers bind, with the number of registrations whose effects implement them. Registrations built in helper methods are not resolved.
- **Modes**: registrations with a `TriggerMode` other than `NORMAL`, and `addSimultaneousEffects` calls.
- **Zone-change choke points** (steps 10 to 12): the callers of each reader method.
